# 검토 기록과 당시 결정

Watchlist 종목 상세의 **기록** 탭에서 지금 보는 자료를 연결하고, 당시 읽은 내용과 자신의 생각을 함께 남깁니다. 기존 기업 정보·가격·내 관심 이유 화면을 그대로 사용합니다. 실제 보유 수량은 Portfolio가 소유합니다.

## 화면에서 하는 일

1. 검토 기록 시작을 누르고 미리보기를 확인합니다. 조사 중·검토 중·보유 단계·보관 단계는 사용자가 직접 선택합니다. 실제 거래나 보유를 자동으로 추정하지 않습니다.
2. 기록 남기기에서 생각·불확실성·사용자가 보고한 시점·가격 시나리오를 선택합니다. 모든 글은 선택 사항이고 실제 저장 시각은 별도로 남습니다. 현재 투자 이유는 기존 이유 화면에서 수정합니다.
3. 보존할 자료와 저장 크기를 읽고 확인하면 당시 기록이 만들어집니다. 새 이유로 기록·일부 변화·새 검토 시작은 이전 기록과 연결하며, 이전 본문을 다시 쓰지 않습니다.
4. 당시 기록에서는 보존한 본문과 지금 원본의 상태를 함께 읽습니다. 이후 자료 연결은 당시 본문을 유지합니다. Portfolio 투자 리뷰의 정확한 종목에서 이 화면으로 이동하고 다시 돌아갈 수 있습니다.

Case는 현재 자료의 연결과 검토 단계입니다. 결정 기록 전체는 개인 가설(`hypothesis`, `reuseAsEvidence=false`)이며 Canonical 보고서·외부 근거 검색에 등록하지 않습니다. Agent의 초안·반박은 명시적으로 요청하며 자동 저장하지 않습니다. AI 없이 모든 수동 기능이 동작합니다.

## 보존과 삭제

- 기업 분석, 직접 고른 딥 리서치, 거시 맥락, 가격·내 기준, 투자 이유·조건, 이유 검증, 투자 리뷰, 기준 충족 여부의 읽기용 허용 필드를 보존합니다. 원본 ID·판본·입력 지문·방법·기록 시각을 함께 남깁니다.
- 자료가 없거나 동일 종목인지 확인할 수 없으면 그 사유를 남깁니다. 특히 과거 투자 리뷰의 ticker만 있는 행에 현재 시장 정보를 소급 적용하지 않습니다.
- 한 기록은 전체 UTF-8 JSON 기준 최대 5 MiB입니다. 자동 만료는 없고, 초과하거나 민감 내용이 발견되면 원본을 정정하거나 보존 항목을 명시적으로 제외해야 합니다. 조용한 잘라내기는 하지 않습니다. 원시 HTML/PDF·첨부·기기 경로·자격 증명·전체 대화는 복사하지 않습니다.
- 앱에서 연결된 기업 분석·딥 리서치 원본을 삭제할 때는 영향받는 기록을 먼저 보여줍니다. 기본은 연결 보존본문도 삭제합니다. 보존본 유지는 별도 선택과 확인을 요구합니다. 파일 탐색기에서 원본을 지운 경우에는 원본 부재와 보존본을 구분하며 별도 삭제가 가능합니다.
- 기록의 보존본문 전체 삭제는 개인 글·사용자보고시점·선택 시나리오·입력 본문을 지웁니다. 식별자·실제 기록 시각·삭제 표시는 남습니다. 이미 만든 백업에 담긴 본문은 별도로 관리해야 합니다.

## 저장과 중단 복구

`market-memory.sqlite3`의 `investment_cases`, `investment_case_events`, `decision_journal_index`, `decision_journal_links`, `investment_case_operations`, `decision_journal_corrections`가 참조·상태를 소유합니다. 본문은 `data/decision-journals/<id>.json`에 둡니다. 기존 workspace 경로와 공통 원자적 교체를 사용하며 처음 읽기만 할 때는 저장소를 만들지 않습니다.

미리보기는 15분 동안만 유효합니다. 원본 또는 Case 판본이 바뀌면 다시 확인해야 합니다. 저장 중단 시 고정된 본문·ID·시각을 검증하여 복구하며 최신 자료로 대신 만들지 않습니다. 파일이 없거나 달라졌으면 미완료 저장의 명시 취소 후 새로 시작합니다. 시작한 삭제는 완료 방향으로만 복구합니다. 이전 삭제 이후 같은 이름의 새 보고서가 생겨도 새 보고서는 삭제하지 않습니다.

주요 API는 `/api/investment-cases/{instrumentId}`, `/preview`, `/confirm`, `/operations/{id}`, `/source-delete-preview`와 `/api/decision-journals/{id}`입니다. 모든 변경은 서버가 만든 미리보기 token과 operation ID를 사용합니다. 오류는 입력 오류·판본 충돌·복구 필요·저장소 불가로 구분하며 기기 경로를 노출하지 않습니다.

## 검증

`py -3 -m pytest features/investment_case/tests -q`는 실제 SQLite/JSON 저장, 당시 내용 유지, 판본 충돌, 크기·민감 범위, 중단·취소·삭제 복구, 다른 경로 복원, 정확한 Agent 범위와 HTTP 계약을 검사합니다. `web/tests/e2e/investment-case.spec.ts`는 격리된 임시 FastAPI 서비스로 저장·새로고침·원본 변경·삭제·왕복 링크와 접근성을 검사합니다. 기존 가격·기준·이유·투자 리뷰·Agent와 보고서 삭제 회귀 검사도 적용합니다.
