# Folio Board 디자인 시스템

> **이 문서가 디자인 언어의 단일 기준이다.** 화면을 새로 만들거나 구조·스타일·상호작용을 바꿀 때 이 문서를 먼저 읽는다.
> 화면 구조·라우트·Agent Dock 동작·화면별 고정값은 [README.md](README.md)가 담당한다.
> 구현의 단일 출처는 `public/styles.css` 하나다 — 토큰은 `:root` / `:root[data-theme="dark"]` 블록, 프리미티브는 파일 **말미**의 `/* 프리미티브 */` 블록에 있다(말미여야 하는 이유는 §7 참고).

---

## 0. 한 줄 정의

**조용한 도구, 또렷한 지면.**

Folio Board는 도구로 조작해서 보고서를 읽는 제품이다. 조작 표면(크롬)은 물러나고, 읽기 표면(지면)은 나선다.

크롬의 문법은 브랜드가 아니라 속성으로 정의한다 — **무테 문법**: 테두리 대신 면 대비·여백으로 구분하고, 컨트롤은 회색 fill, 선택은 트랙 위 알약이다(iOS HIG 계열 관습). 여기에 리서치 도구의 정보 밀도(**Folio 밀도**)를 얹는다.

## 1. 두 목소리 (2026-08-08 확정)

디자인 언어는 하나가 아니라 둘이며, 서로 다른 규칙 세트를 가진다. **새 화면은 "어느 목소리인가"부터 정하고 시작한다.**

| | 도구 크롬 (무테 문법) | 보고서 지면 (에디토리얼) |
|---|---|---|
| 어디 | 버튼·패널·필터·설정·목록·도크 | 보고서 리더 본문, 시각화 카드 |
| 구분 | 테두리 없이 면 대비·여백 | 평평한 밝은 지면, 그림자·hover lift 금지 |
| 타이포 | 역할 스케일(`--fs-body` 15px 본문) | 읽기 스케일(`--fs-report-body` 18px 본문) |
| 굵기 | `--fw-normal/medium/bold` 3종만 | 제목에 `--weight-heading`(800) 허용 |
| 인상 | 조용한 회색, 뒤로 물러남 | 딥 네이비 hero + 골드 kicker, 신문·리포트 |

- 리더 화면은 두 목소리가 섞인다: **본문은 지면, 조작 레일·노트 패널은 크롬.**
- 지면의 대표 패턴: `.report-hero`(딥 네이비 배경 + `.report-kicker` 골드 대문자), `.markdown-brief`(밝은 surface, 제한 폭).

## 2. 원칙

1. **구분은 테두리가 아니라 면으로.** 테두리 버튼은 없다(0.5에서 전면 제거). 폼 컨트롤도 무테. 떠 있는 면은 그림자로 구분한다.
2. **깊이가 내려갈수록 가벼워진다.** `.surface` 3단(r18+그림자 → r14 → r10). 3단보다 깊게 중첩하지 않는다 — 더 필요하면 정보 구조가 잘못된 것이다.
3. **신호는 하나면 충분하다.** 의미 표시 왼쪽 액센트는 3px 하나. 카드 배경 워시 금지. `.btn--primary`는 화면/패널당 하나.
4. **색은 의미를 가질 때만 쓴다.** 버건디/골드/블루/틸은 의미색, 퍼플=Personal Overlay, 틸=Thesis Delta. 장식용 색은 없다. 다크 모드도 색이 아니라 어둠으로 위계를 만든다.
5. **데이터 위계가 눈에 보여야 한다.** Canonical / Personal Overlay / hypothesis 3계층 분리(§5 아키텍처 원칙)는 시각 언어에도 대응된다 — Overlay는 퍼플 계열로 분리, 사용자 입력·노트에는 "근거 아님" 경계 표시를 유지한다.
6. **상태와 접근성은 스타일이 아니라 계약.** 선택 상태는 `aria-pressed`가 소유한다. WCAG 2.2 AA 대비, 44px 터치 타깃, 항상 보이는 포커스 링, reduced motion 대응이 공개 화면 계약이다.

## 3. 토큰

어휘 계층: **토큰 → 프리미티브 → 패턴 → 화면.** 아래로 갈수록 위를 재사용만 한다. 새 토큰을 만들기 전에 같은 역할의 기존 토큰이 있는지 먼저 본다.

### 표면 4단

`--surface-page` < `--surface-panel` < `--surface-group` < `--surface-control`. 페이지 < 패널 < 그룹 < 컨트롤 순으로 위계를 만든다. 회색 계열은 cool gray가 아니라 warm white/soft cream/taupe(`--folio-surface-clean/-2/-muted`)이고, dark surface는 black이 아니라 딥 네이비(`--folio-surface-dark`, `--folio-surface-black`도 네이비 alias)다.

### 의미색

| 색 | 역할 |
|---|---|
| 골드 `--folio-gold` | 보고서 kicker·eyebrow, 브랜드 강조 |
| 버건디/골드/블루/틸 (+`-soft` 쌍) | verdict·상태 의미색. 칩 `data-tone`이 소비 |
| 그린/warning | 성공·주의 상태 |
| 퍼플 `--folio-purple` | **Personal Overlay 전용** |
| 틸 `--folio-teal` | **Thesis Delta 전용** + `--folio-accent` |
| `--folio-chart-1~5` | 데이터 시리즈 전용. §"차트 데이터색" 참고 |
| `--market-us/kr/europe/jp` | 시장 색 슬롯. **현재 전부 중립**(2026-08-08 결정: 시장을 색으로 구분해야 하는 화면이 실제로 생길 때 배정하고, 배정 시 verdict 의미색과 겹치지 않게 설계한다) |

accent 위 글자는 `--folio-on-accent`를 쓴다 — accent는 다크에서 밝아져 글자색이 뒤집힌다.

### 차트 데이터색 (2026-09-11 확정)

차트 색은 두 가지 다른 일을 한다 — 먼저 어느 쪽인지 정하고 색을 고른다.

- **범주(categorical)** — 서로 무관한 항목 여럿이 한 그림에 같이 나온다(브리핑 이야기 비중의 뉴스 주제 등). `--folio-chart-1~5` 다섯 색을 쓴다. 감으로 고르지 않는다 — dataviz 스킬의 `validate_palette.js`로 명도대(라이트 0.43~0.77/다크 0.48~0.67)·채도 하한(OKLCH C≥0.10)·색맹 시뮬레이션 구별(ΔE)·배경 대비를 통과한 값만 쓴다. 이전 값은 다섯 색 전부 채도가 0.10 미만이라 탁하게 읽혔고, 색맹 시뮬레이션에서 인접한 색끼리 거의 안 갈렸다(실측).
- **캐스케이드(cascade)** — 매출→영업이익→순이익처럼 같은 값이 비용을 거치며 줄어드는 한 흐름이다. 서로 다른 항목이 아니라서 범주 색 여러 개를 섞으면 알록달록해지고, 어느 차트를 보는지 색이 말해주지 않는다. `FundamentalsPanel.tsx`(워치리스트 분기 지표)가 먼저 쓰던 규칙을 그대로 가져온다 — 첫 계열(규모 기준)은 무채색 잉크(`color-mix(in srgb, var(--folio-ink) 42%, transparent)`), 나머지는 그 차트만의 색 하나(`--folio-chart-N` 또는 아래 전용 토큰)와 `color-mix(in srgb, <그 색> 45%, transparent)`로 만든 옅은 톤뿐이다. 단위가 다른 값이 하나 섞이면(실적 차트의 순이익률처럼 금액 사이에 낀 비율) 그 계열만 별도 색을 받는다.
- **범주 색과 캐스케이드 색은 값이 갈릴 수 있다.** 캐스케이드 색은 한 차트 안에서 자기 자신의 옅은 톤하고만 붙고 다른 네 범주 색과 나란히 놓일 일이 없어서, 범주 팔레트가 요구하는 "다섯 색 모두 상호 구별" 제약이 없다. 실측으로 이 자유를 실제로 썼다 — 기업분석 순이익률 선(다홍 계열, `--folio-chart-accent-ratio`)과 현금흐름 색(`--folio-chart-accent-cashflow`)은 범주 자리에 넣으면 초록(`--folio-chart-3`)과 색맹 시뮬레이션에서 구별이 안 되지만, 각자 자기 차트에서 초록과 만날 일이 없어 안전하다. 실적/분기 흐름의 막대는 초록과 안 부딪히는 `--folio-chart-1`(파랑)을, 마진 추이는 `--folio-chart-5`(보라)를 그대로 재사용한다 — 값이 갈리지 않는 색까지 새 토큰으로 쪼개지 않는다.
- **차트 마크는 정지 상태만 있다.** 그라디언트·유리질감(glassmorphism)·hover 시 glow/확대를 마크(막대·선·점) 단위로 시제품까지 만들어 검토했지만 채택하지 않았다(2026-09-11) — 보고서 지면은 그림자·hover lift가 없다는 원칙(§2 원칙 1, elevation)을 차트 마크에도 그대로 적용한다. 다시 검토하지 않는다.

### 모서리 4종

`--r-control`(10) / `--r-group`(14) / `--r-panel`(18) / `--r-pill`. **px를 직접 쓰지 않는다.** 레거시 `--folio-radius(-lg)`는 별칭으로만 남아 있고 새 코드에서 쓰지 않는다. 예외: 캘린더 격자(`.cal-cell`)의 hairline·자체 모서리, 진행바·스트라이프 같은 1~3px 장식 슬라이버.

### 굵기

크롬은 `--fw-normal`(400) / `--fw-medium`(600) / `--fw-bold`(700) 3종만. 강조는 굵기가 아니라 크기·색·여백으로 만든다. `--weight-heading`(800)은 **보고서 지면 제목 전용**이다(2026-08-08 재분류 — SUIT 800과 IBM Plex Sans 700의 광학 두께를 맞추는 용도. 크롬에서 쓰지 않는다).

### 타이포 — 정본 선언 (2026-08-08 확정)

두 스케일은 "레거시 vs 신규"가 아니라 **목소리당 하나**다.

- **도구 크롬 정본 = 역할 스케일(px)**: `--fs-caption`(10, 차트 축·워터마크) / `--fs-label`(11, 배지·eyebrow) / `--fs-meta`(12.5, 보조 정보) / `--fs-body-sm`(13.5, 설명문) / `--fs-body`(15, 본문·수치) / `--fs-title-sm`(16.5, 카드 제목) / `--fs-title`(20, 패널 제목). 수치(value)는 `--fs-body` + `--fw-bold` + `tabular-nums`.
- **보고서 지면 정본 = 읽기 스케일(rem)**: 본문 `--fs-report-body`(18px), 제목 `--fs-xl`(30px, 모바일 clamp 26~30), 섹션 `--fs-2xl`/`--fs-lg`/`--fs-md`(34/24/20px).
- **회수 대상**: 크롬 코드가 쓰는 `--fs-base`(17px)·`--fs-sm` 등 rem 스케일. 일괄 치환하지 않고 **그 화면을 만질 때** 역할 스케일로 옮긴다. 새 크롬 코드는 역할 스케일만 쓴다.
- 화면별 고정값(RSS 카드 제목 22px, 브리핑 차트 20px 등)은 [README.md](README.md)의 화면별 항목이 관리한다.
- **수치 표기 계약**: 단독으로 읽히는 수치(시세·평가액·비중·수익률)는 `tabular-nums` + `--fw-bold`로 세로 정렬을 지킨다. 전화번호·티커처럼 숫자가 식별자인 곳에는 쓰지 않는다. 수치 전용 폰트(모노 램프)는 도입하지 않는다.

### 간격·터치

간격은 4/8 리듬 `--sp-1~8`(4/8/12/16/20/24/32). 모바일 터치 타깃은 `--touch-min`(44px)으로 **실제 요소 박스**를 올린다(`::before` 히트 영역 확장 금지 — 검증이 getBoundingClientRect로 실제 박스를 잰다). 인접 간격 8px은 컨테이너 gap이 담당한다.

### elevation

`--elev-1`(정지 크롬) / `--elev-2`(hover/raised) / `--elev-overlay`(모달). **입력·필터 패널과 좌우 레일만** elevation을 쓴다. 보고서 지면(`.markdown-brief`, `.briefing-visual-card`)에는 shadow·hover lift를 적용하지 않는다(원칙 1·두 목소리).

### 다크 대응쌍 규칙

- 색은 전부 `:root`와 `:root[data-theme="dark"]`의 토큰으로만 쓴다. 본문에 밝은 색 리터럴(`#fff`, `rgba(255,255,255,…)` 등)을 직접 쓰지 않는다.
- **토큰을 새로 만들면 다크 쌍을 반드시 함께 정의한다.** 정의가 없으면 라이트 fallback이 다크에 고정되거나(대비 파괴), fallback 없는 선언이 통째로 무효가 된다(포커스 링 소실). `web/tests/workLogCopySource.test.mjs`가 검사한다.
- 다크 표면은 색상 222°에 채도 16~24%(배경 `#0d0f12`, 카드 `#1c202b`, 테두리 `#2e374c`). 완전 무채색은 화면이 죽고 원 채도는 남색으로 튄다. 강조색은 색상을 유지하고 채도만 10%p 낮춘다.
- 반투명 표면·잉크 틴트(`--folio-tint-weak/strong`, `--folio-surface-translucent/float/veil`, `--folio-toggle-track`)는 두 테마에서 각각 정의한다.
- **세그먼트 선택 알약의 상태는 면이 아니라 높이와 잉크가 나른다**(2026-08-09 확정). 다크는 트랙 대비 3:1을 넘지만(`#666e82` vs `#1f2430` = 3.04) 라이트는 흰 알약을 밝은 회색 트랙에 얹는 구조라 1.15에 그친다 — 3:1을 색으로 맞추려면 트랙을 크게 어둡게 내려야 하고, 그러면 앱에서 가장 자주 보이는 컨트롤 11곳이 전부 무거워진다. 대신 세 신호를 겹친다: `--segment-thumb-shadow`(알약 크기에 맞춘 1px 그림자 — `--elev-1`은 패널용이라 이 크기에서 퍼진다), 잉크 차이(라이트 2.31, 다크 1.92), 그리고 `aria-pressed`. WCAG 1.4.11은 상태가 텍스트로도 전달되면 예외를 둔다. **글자 대비는 예외 없이 지킨다** (선택 18.94/5.10, 비선택 7.11/8.06). 새 세그먼트를 만들 때 알약 색만 바꿔 3:1을 맞추려 하지 않는다.

## 4. 프리미티브

**새 화면은 이 4종 + 폼 컨트롤만 쓴다.** 정의는 `public/styles.css` 말미 프리미티브 블록 하나다. 화면 전용 CSS에서 이들의 **모양을 다시 선언하지 않는다** — 배치만 갖는다.

| 프리미티브 | 무엇 | 변형 |
|---|---|---|
| `.btn` | 모든 버튼 | `--primary`(어두운 fill) / 기본(회색 fill) / `--text`(투명) × `--danger`(파괴) × `--sm`(32px) / `--icon`(정사각, `--r-control`) |
| `.surface` | 패널 면 | `--group`(패널 안 그룹) / `--inset`(가장 안쪽) |
| `.chip` | 비대화형 상태 표시 | `data-tone="muted|burgundy|gold|blue|teal"` |
| `.segment` | 상호배타 선택 | 항목 수 무관. 좁으면 가로 스크롤 |

### `.btn` 변형 선택

- **`--primary`**: 그 화면/패널에서 **하나**. 생성·저장·전송처럼 사용자가 여기 온 이유인 동작.
- **기본(회색 fill)**: 나머지 실행 버튼 전부. 초기화·새로고침·내보내기.
- **`--text`**: 취소·닫기처럼 되돌리는 동작, 또는 목록 안에서 반복돼 fill이 시끄러운 경우.
- **`--danger`**: 파괴 동작 전용(삭제·초기화처럼 데이터가 사라지는 동작). 트리거 단계는 조심 신호만 — 회색 fill에 버건디 글자. **진한 버건디 fill(`.btn--primary.btn--danger`)은 확인 단계의 최종 버튼에만** 쓴다. 데이터가 사라지지 않는 동작(로그아웃·작업 취소)에는 쓰지 않는다.
- **테두리 버튼은 없다.**

**저장은 변경이 있을 때만 주인공이다.** 설정처럼 저장 패널이 여러 개 쌓인 화면에서 저장 버튼은 평소 회색이고(변경 없이 누르면 "변경 사항이 없습니다"를 그 자리에서 말한다), **변경이 생긴 패널의 저장만 `--primary`로 진해지며** "저장 안 된 변경" 힌트가 붙는다. 진한 버튼이 곧 저장 안 된 변경의 신호가 되므로 disabled가 필요 없어진다. 여러 패널이 보이는 화면의 primary 상한은 패널당 하나다.

선택 상태는 `aria-pressed="true"`가 소유한다. `.active` 클래스로 칠하지 않는다 — 레거시 `.filter-btn.active`는 마크업에만 있고 규칙이 없어 Work Log 필터가 선택 상태를 보여주지 못했다.

**disabled를 기본 상태로 쓰지 않는다.** 비활성 버튼은 눈에 띄지 않고 무엇이 부족한지 설명하지 못한다. 버튼은 눌리게 두고, 눌렀을 때 빠진 것을 그 자리에서 말한다 — 엔진이 없으면 숨기지 않고 규칙 fallback으로 내려가는 제품 원칙과 같은 결이다. 제출 중 이중 클릭 방지 같은 일시적 잠금에만 disabled를 쓴다.

**맨 아이콘을 버튼으로 쓰지 않는다.** 아이콘 버튼은 항상 `.btn--icon`의 fill 배경을 갖는다 — 배경이 없으면 눌린다는 것이 보이지 않는다. 배경 없는 아이콘은 상태 표시(경고)나 행 전체가 눌린다는 어포던스(펼침 화살표)로만 쓴다.

**모양 문법**: 알약·원(`--r-pill`)은 칩·세그먼트의 **상태·선택 언어**이고, 모서리 사각(`--r-control`)은 버튼·입력의 **실행 언어**다. 아이콘 버튼도 실행이므로 원이 아니라 버튼과 같은 모서리를 쓴다(2026-08-08 결정).

### 폼 컨트롤도 같은 언어

`input` / `select` / `textarea`는 버튼과 **같은 무테 회색 fill**, 높이 36px.

- 컨트롤에 `border`를 다시 주지 않는다. 상태는 hover 배경과 `:focus-visible` 링이 표현한다.
- 라벨이 붙은 select는 래퍼(`.gen-option`)가 면을 갖고 **안쪽 select는 면을 그리지 않는다**(상자 안 상자 방지).
- `textarea`만 여러 줄이라 높이 예외다.

폼 동작 계약:

- placeholder에는 예시만 둔다. 입력을 시작하면 사라지므로, 형식·조건 같은 중요한 정보는 필드 아래 안내문에 둔다.
- 검증 메시지는 해당 필드 옆에 한 번에 하나만 보여준다. 제출 시점에 몰아서 띄우지 않는다.
- 필수/선택 표기는 **소수인 쪽에만** 붙인다(필수 5개·선택 1개면 선택에만).

### `.segment` 사용 경계

- 세그먼트는 **같은 뷰**의 필터·표시 형식 전환·상호배타 선택이다. 다른 콘텐츠로 이동하면 그건 탭·네비게이션이다. 한 세그먼트의 내용이 다른 세그먼트에도 있을 법하면 세그먼트가 맞다.
- 예/아니오 같은 이진 on/off에는 쓰지 않는다(체크박스가 맞다).
- 5개를 넘으면 세그먼트가 맞는지 먼저 의심한다. 시장 필터(US/KR/EUROPE/JP…)처럼 같은 성격의 항목이 늘어나는 경우만 가로 스크롤로 수용하고, 라벨이 길거나 성격이 다른 항목이 섞이면 다른 패턴을 쓴다.

## 5. 패턴

### `.surface` 3단 중첩

```text
.surface            페이지 배경 위 최상위 패널   r18 + elev-1
  .surface--group   패널 안 묶음 면              r14, 그림자 없음
    .surface--inset 가장 안쪽(코드·인용·값)      r10, 그림자 없음
```

같은 무게를 두 번 주면 액자가 이중으로 보인다(브리핑 설정에서 실재 — 바깥 r18+그림자 안에 또 r18+그림자). 패널 제목을 fieldset처럼 테두리 위에 띄우지 않는다 — 테두리를 없애면 제목 배경 조각만 흰 사각형으로 남는다. 제목은 흐름 안의 라벨로 둔다.

기존 패널 클래스(`.cockpit-panel`·`.input-panel`)는 BEM 부모라 유지하되 모양은 프리미티브 토큰에서 읽는다. **새 패널은 `.surface`를 직접 쓴다.**

### 훅 클래스

의미색·화면별 배치가 필요하면 프리미티브 **뒤에 훅을 덧붙인다**. 프리미티브가 기하를, 훅이 색·배치를 갖는다.

```tsx
<span className="chip status-chip" />           {/* 기하=chip, 색=조상 규칙이 status-chip으로 */}
<button className="btn report-action-btn" />     {/* 기하=btn, 풀폭·좌측정렬=레일 규칙 */}
```

훅을 함부로 지우지 않는다 — Change Feed 카드 안에는 상태 칩과 판정 칩이 함께 있어, 훅 없이 `.chip`만 남기면 조상 규칙이 두 칩을 같은 색으로 칠한다.

### 액센트와 워시

- 카드·패널의 의미 표시 왼쪽 줄은 **3px 하나**(0.5.1에서 25곳 통일). `border-left: 1px`는 액센트가 아니라 패널 가장자리·구분선이므로 그대로 둔다.
- 카드 전체에 옅은 색을 까는 배경 워시 금지. 카드가 늘어서면 항목마다 배경이 다른 것처럼 보이고, 본문 대비가 카드 안에서 좌우로 달라진다. 표시가 필요하면 줄 하나면 충분하다.

### 포커스와 hover

포커스와 hover는 한 규칙으로 묶지 않는다. 카드가 떠오르는 것은 마우스 되먹임이지 포커스 표시가 아니다. **포커스 링은 styles.css 말미의 `focus-visible` 블록이 소유하며** 화면별 CSS에서 다시 선언하지 않는다.

### 특이성

- 화면 CSS에서 `min-height`를 다시 박지 않는다 — 특이성 높은 화면 규칙이 모바일 터치 규칙 `.btn`을 이겨 44px 타깃이 무너진 사례가 있다. 데스크톱 전용 크기가 정말 필요하면 `@media (min-width: 769px)` 안에 둔다.
- 컨테이너에서 자손 `button`을 통째로 칠하지 않는다(세그먼트 알약까지 덮어쓴 사례가 있다).

### 죽은 CSS는 지운다

참조하는 컴포넌트가 없는 규칙은 걷어낸다. 단, **셀렉터에 등장하는 모든 클래스가 죽었을 때만** 지운다. 접두사 비교는 `.portfolio-weight`(살아 있음)를 `.portfolio-weight-row`(죽음)에 걸어 산 것까지 지운다.

### 대화 안 카드 (Agent 도크)

도크 메시지 안에 렌더되는 카드(수정 제안, 짚어보기 답변, 노트 스냅샷)는 화면이 아니라 대화의 일부다.

- 카드당 액션은 **최대 2개**, 카드 하단에 둔다. 수정 제안의 승인/거절이 기준 모양이다.
- 데이터 포인트는 4~5개까지. 넘치면 요약하고 리더/화면으로 여는 링크를 단다.
- 카드 안 세로 스크롤·드릴인(카드 속 다중 뷰)·드롭다운 금지. 높이는 내용에 맞춰 늘어나고, 상세는 도크가 아니라 리더가 담당한다.
- **실행은 버튼, 해석은 입력창.** 준비된 동작의 확정(승인·거절·저장)은 카드 버튼으로, 자유 텍스트·수정 요청·해석이 필요한 것은 채팅 입력으로 보낸다. 개인 맥락을 읽거나 저장물을 바꾸는 것은 언제나 명시적 action이다(Agent 실행 경계).

### 로딩은 스켈레톤

인라인 콘텐츠(카드·목록·도크 카드)의 로딩은 회전 스피너가 아니라 **최종 레이아웃을 닮은 스켈레톤**으로 보여준다. 자리를 먼저 잡아 로드 후 레이아웃 점프가 없어야 한다. 오래 걸리는 생성 작업은 반대로 기존 진행바와 소요 시간 안내를 유지한다 — 스켈레톤은 "곧 온다"를, 진행바는 "얼마나 걸린다"를 말한다.

### 리포트 표 (`.markdown-brief table`, 0.6)

브리핑·기업분석 리더가 렌더하는 markdown 표는 셀 하나하나를 본다 — 열 위치가 아니다. 같은 표 안에도 "확인되지 않음" 같은 텍스트 값과 "$8.25B" 같은 숫자 값이 섞이고, 리스크·체크포인트 표는 라벨 열 말고는 전부 산문이라 "첫 열=라벨, 나머지=숫자" 같은 열 규칙이 안 통한다(`public/app.js::renderMarkdown()`의 `NUMERIC_CELL` 정규식이 셀 텍스트로 판정해 `class="num"`을 붙인다).

- **테두리 대신 여백** — 세로 테두리 없이 가로 구분선만, 헤더는 골드(`--folio-gold`) 밑줄 2px + 대문자 라벨로 구분한다(실측: 예전엔 헤더·본문 배경이 거의 안 구별됐다).
- **숫자 열만 `.num`** — 오른쪽 정렬 + `font-variant-numeric: tabular-nums` + `var(--font-mono)` + nowrap. 값이 좁은 열에서 줄바꿈되지 않게 하는 유일한 장치이며, 셀 판정이라 산문 열은 건드리지 않는다.
- **첫 열은 `nowrap` 대신 `max-width: 40%`** — 라벨이 길면(리스크 표) 그 열이 표 폭을 독차지해 산문 열이 쥐어짜인다(실측 93px). `word-break: keep-all`이 이미 있어 짧은 라벨("매출")은 끊을 공간이 없어 한 줄을 유지하고, 긴 라벨은 필요하면 두 줄로 접힌다.
- **`word-break: keep-all` 필수** — 한글은 띄어쓰기 없이도 음절 경계마다 끊겨, 좁은 열에서 "무엇을 훼손하나"가 7줄로 쪼개진 사례가 있었다. 캘린더 표(`.briefing-calendar-table`)가 먼저 쓰던 규칙을 전체 표로 넓혔다.
- **첫 열 `position: sticky`** — 가로 스크롤 중에도 지금 보는 값이 어느 행인지 화면에 남는다. 배경을 명시하고(스크롤되는 다른 열이 밑으로 비치지 않게), 줄무늬 행은 그 색까지 맞춘다(`tr:nth-child(odd) td:first-child`).
- 모바일 전용 `display: block` 오버라이드를 표에는 걸지 않는다 — table-row/cell 형태가 깨져 sticky가 자리를 잃는다. `.table-wrap`이 이미 모든 폭에서 `overflow-x: auto`를 갖고 있어 필요 없다(`pre`는 계속 그 규칙을 쓴다).

섹션 요약 blockquote(`> `)는 헤딩 바로 다음(사이 빈 줄 허용)에 올 때만 `.section-summary`로 렌더된다 — `renderMarkdown()`이 직전에 push한 노드가 `<h3>`(=markdown `## `, 보고서 자체 제목 `# `이 h2를 쓰는 시프트)인지로 판정한다. 본문 중간의 일반 인용은 같은 blockquote 스타일을 그대로 쓰되 골드 라벨이 안 붙는다. 레거시 bridge(`app.js`)와 React 폴백(`MarkdownRenderer.tsx`) 둘 다 같은 규칙을 구현한다 — 헤딩 레벨 매핑이 갈리면(#6에서 실측: 폴백이 `##`→h2, bridge는 h3) 판정도 갈린다. **`h3 + blockquote`는 다른 헤딩-다음-요소와 같은 간격 규칙(`.markdown-brief h3 + p/ul`, 0.58em)에 반드시 포함시킨다** — `h3`는 `margin-bottom: 0`, `blockquote`는 `margin: 0 0 1em`(top 0)이라 이 셀렉터를 빠뜨리면 소제목과 섹션 요약이 간격 없이 붙는다(0.6 P3 실측: 사용자가 "소제목과 섹션요약 사이 간격이 비정상적으로 좁다"로 지적, `getComputedStyle` 확인 결과 0px였다).

## 6. 하지 않는 것

- 테두리 버튼, 컨트롤 `border`, fieldset식 제목 띄우기
- `border-radius`/`font-weight`/크기 px 직접 입력 (토큰만)
- `.active`로 선택 상태 칠하기 (`aria-pressed`가 소유)
- 맨 아이콘 버튼(아이콘 버튼은 항상 fill 배경), 습관성 disabled(눌리게 두고 이유를 말한다)
- 도크 카드 안 드롭다운·세로 스크롤·드릴인, 이진 on/off에 세그먼트
- 카드 배경 워시, 4px·2px 액센트 줄
- 본문에 밝은 색 리터럴, 다크 쌍 없는 토큰
- 보고서 지면에 shadow·hover lift
- 크롬 새 코드에 rem 타이포 스케일(`--fs-base` 등), 800 굵기
- Tailwind·shadcn·새 UI 프레임워크·새 폰트·새 아이콘 라이브러리 (명시 요청 없이)
- ui-ux-pro-max 스킬을 새 디자인 시스템 생성기로 쓰는 것, `--persist`/`design-system/` 폴더 생성 (명시 요청 없이)

### 첫 실행 안내 화면 (0.5.1)

**예외가 없다.** 배경은 뒤에 떠 있는 앱을 블러 처리한 것이고, 앱의 전체 화면 모달(`.home-mode-chooser-backdrop`)과 같은 문법이다 — 어두운 scrim + `backdrop-filter`. 카드가 불투명해서 본문 대비는 뒤 화면과 무관하다.

시안 단계에서 배경 색면(blue/gold/teal 블러)을 검토했고 원칙 3("카드 배경 워시 금지")의 화면 한정 예외로 한 번 승인했지만, 뒤 화면 블러로 바꾸면서 철회했다(2026-08-08). 앱이 비치는 쪽이 "건너뛰면 바로 이거"를 더 잘 말하고, 예외도 남기지 않는다.

나머지도 전부 계약대로다 — 모서리 4종(`--r-panel`/`--r-group`/`--r-control`), 크롬 역할 스케일, 굵기 3종, 44px 터치 타깃, `--folio-on-accent`.

**시장을 색으로 구분하지 않는다.** 처음에는 시장 표식에 blue/burgundy/teal/purple을 썼는데 퍼플은 Personal Overlay 전용, 틸은 Thesis Delta 전용이라 의미색 계약을 깬다. 라벨이 이미 `US`/`KR`/`EU`/`JP`를 말하므로 표식을 없앴다(원칙 4 — 장식용 색은 없다). `--market-*` 슬롯은 계속 중립이다.

**눌린 면과 CTA는 블루가 아니다(0.5.3 수정).** 신설 당시 `--folio-blue`를 눌린 칩·CTA·진행 막대·순번에 채웠는데, 블루는 verdict 칩(`data-tone="blue"`)이 쓰는 의미색이라 §1 원칙 4를 깬다 — 이 절이 "예외가 없다"고 적어 둔 것과도 어긋났다. 실측으로 이 화면의 CTA는 `rgb(122,182,234)`인데 앱의 `.btn--primary`는 같은 패널에서 `rgb(11,12,15)`라, 첫 화면만 톤이 달랐다. 지금은 `.btn--primary`·`.sym-chip[aria-pressed="true"]`와 같은 잉크 면(`--folio-surface-dark` + `--folio-ink-inverse`)을 쓴다. 진행 막대 채움만 `--folio-ink`인데, 트랙(`--surface-control`) 위에서 두 테마 모두 대비가 서는 값이 그것뿐이기 때문이다 — `--folio-surface-dark`를 쓰면 다크에서 `#0b0c0f`가 `#1f2430` 트랙에 묻힌다. 포커스 링(`--folio-focus`)만 계속 블루다. 그건 앱 전역 계약이다.

> 다크에서 CTA와 카드 면의 대비는 1.07:1이다. **앱의 `.btn--primary`가 같은 패널에서 정확히 같은 값**이라 이것은 안내 화면의 문제가 아니라 앱 전역의 다크 primary 계약이다. 글자 대비가 17.93:1이라 버튼은 글자로 식별되지만, 다크에서 primary와 secondary가 가까워 보이는 것은 사실이다. 바꾸려면 안내 화면이 아니라 `.btn--primary`부터 바꿔야 한다.

**튜토리얼(0.5.3)**: 완료 단계의 선택 흐름이다. 진행 막대의 단계로 세지 않는다 — 선택이지 절차라서 단계로 세면 건너뛸 수 없는 것처럼 읽힌다. 흐름 도해는 **큰 SVG가 아니라 HTML 박스 + 1px 연결선**이다. 860px 카드에 맞춘 도형은 375px에서 글자가 뭉개지고, 박스는 모바일에서 세로로 접히며 글자가 진짜 텍스트라 확대·번역·스크린리더가 그대로 읽는다. 단계를 색으로 구분하지 않는다(원칙 4).

**화면 로컬 토큰 둘**: `--wz-spring`(튕기는 이징 — 전역 `--ease`는 `ease`라 이 느낌이 없다), `--wz-title`(27px — 패널 제목이 아니라 화면의 유일한 제목이라 `--fs-title` 20보다 크다). `:root`를 건드리지 않고 `.welcome-shell`에 둔다.

## 7. 구현 주의

프리미티브 블록은 **반드시 styles.css 파일 말미에 둔다.** 앞쪽 레거시 규칙이 같은 특이성으로 이기는 사고가 실재했다. 프리미티브 뒤에 새 화면 CSS를 추가하지 말고, 화면 CSS는 프리미티브 블록 앞에 둔다.

**같은 특이성의 텍스트 클래스를 콜아웃 클래스에 겹쳐 걸지 않는다.** 두 클래스가 같은 속성을 선언하면 파일 뒤쪽이 이긴다 — `class="settings-hint react-dashboard-error"`는 빨간 테두리·분홍 면은 그대로인데 글자만 회색 400이 되어(실측 `rgb(68,80,95)`), 오류처럼 보이지 않는 오류 상자가 됐다. 콜아웃은 콜아웃 클래스 하나만 건다.

관련 자동 검사: `web/tests/reactTypographySource.test.mjs`(타이포), `web/tests/themePreferenceSource.test.mjs`(테마), `web/tests/workLogCopySource.test.mjs`(토큰 정의 누락), `web/tests/tooltipHitArea.test.mjs`(히트 영역). 새 계약을 추가하면 검사도 함께 늘린다.

## 8. 새 화면 체크리스트

0. **어느 목소리인가** — 도구 크롬인지 보고서 지면인지 먼저 정한다(§1).
1. 가장 가까운 기존 화면을 데스크톱·모바일로 열어 재사용할 패턴을 먼저 찾는다.
2. 버튼·칩·세그먼트는 프리미티브로 시작한다. 새 클래스를 만들기 전에 훅으로 되는지 본다.
3. 새 CSS에 `border-radius`/`font-weight`/크기 숫자가 들어가면 멈추고 토큰을 쓴다. 크롬 타이포는 역할 스케일만.
4. 375px에서 가로 스크롤이 없는지, 대화형 요소가 44×44인지 확인한다.
5. Light/Dark 양쪽에서 본다. 새 토큰은 다크 쌍까지 정의했는지 본다.
6. 키보드로 순회해 포커스 링이 항상 보이는지 본다.
7. 로딩·빈 상태를 설계했는지 본다 — 인라인은 스켈레톤, 긴 생성 작업은 진행바 + 소요 시간 안내.
