# 정책 사건

공식 결정문을 확인한 사용자 또는 Agent가 초안을 작성하고, 미리보기 뒤 사용자가 명시적으로 저장합니다. 금리 원자료의 변화나 캘린더 일정은 정책 결정으로 자동 등록하지 않습니다.

- `POST /api/macro/policies/preview`: 공식 원문 링크·인용·진행 단계·반대 조건·다음 확인을 검증합니다. 쓰기는 없습니다.
- `POST /api/macro/policies/confirm`: 미리본 내용의 지문과 사용자 확인, 공식 출처 확인이 모두 있어야 저장합니다. 내용이 바뀌면 다시 미리봅니다.
- `GET /api/macro/policies`: 저장된 사건 이력을 읽습니다. 조회로 DB를 만들지 않습니다.
- 저장 위치는 기존 `data/market-memory.sqlite3`의 `macro_policy_events`입니다. 추가 전 SQLite 백업을 만들고 이력을 덮어쓰지 않습니다. 같은 미리보기의 재시도는 같은 기록을 반환합니다.
- 정책 유형·진행 단계·전달 채널은 enum으로 검증합니다. 날짜를 모르면 비워 두며, 각 채널은 자체 공식 출처를 갖습니다. URL만으로 공식성을 보증하지 않으며 확인 단계에서 원문을 대조해야 합니다.
- 기업 노출·사용자 이유의 연결은 별도 검증된 항목만 허용하며 이 입력 API에서 ticker를 임의 연결하지 않습니다. 기사 동시 등장으로 연결하지 않습니다. 확률·선거 결과·투자 지시는 출력 계약에 없습니다.

0.8 화면에는 입력 양식을 두지 않습니다. 필드를 직접 채우는 방식은 번거로워 쓰이기 어렵다고 판단했고, 공식 원문 링크로 Agent가 초안을 채우거나 공식 발표를 후보로 띄우는 방식으로 후속 버전에서 다시 연결합니다. API·저장·검증은 그대로 유지합니다.

검증: `py -3 -X utf8 -m pytest features/macro_policy -q`

## 기업·개인 조건 연결

채널마다 공식 sourceRef가 필요합니다. `GET /api/macro/policies/targets/{ticker}`로 저장된 공시 노출과 현재 이유 개정의 조건을 읽습니다. 미리보기는 정확한 profileId/exposureId를 검증하고 원문을 가져오며, 종목명 동시 등장으로 연결하지 않습니다. 개인 조건은 정확한 현재 revisionId/index와 전달 설명·조건에 모두 존재하는 명시적 공통 표현을 확인합니다. 조건은 hypothesis로 보존합니다. 확인 직전 입력이 달라지면 저장을 거부하고 다시 미리보기해야 합니다.
