# features/onboarding

첫 실행 여부를 판정하고, 안내를 끝냈다는 기록을 남깁니다.

## 담당 범위

- `service.py` — `onboarding_status()`, `complete_onboarding()`, `has_user_data()`
- 저장 위치 — `data/onboarding-state.json` (`completedAt`, `skipped`)
- 화면 — `web/src/app/WelcomeWizard.tsx` (`web/src/app/App.tsx`가 띄웁니다)

## 첫 실행 판정

**"안내 파일이 없다"를 첫 실행으로 보지 않습니다.** 그 파일은 배포 zip에 없으므로, 그렇게 잡으면 쓰던 사람이 새 버전으로 올릴 때마다 처음 쓰는 사람 취급을 받습니다 — 브리핑 50개와 기사 22,548개를 가진 사람에게 "환영합니다"를 띄우는 셈입니다.

그래서 **사용자가 만든 것이 하나라도 있으면 첫 실행이 아닙니다.**

```text
firstRun = 안내 기록 없음 AND 사용자 자료 없음
```

사용자 자료의 기준은 `USER_FILES`(portfolio·watchlist·market-scope·obsidian-settings), `USER_DIRS`(briefings·company-analysis·topic-reports·notes·agent-threads), `INBOX_DIRS`(rss·articles·reports·filings)입니다.

서버가 스스로 만드는 파일은 이 목록에 넣지 않습니다. 실측으로 빈 워크스페이스에서 서버를 처음 켜면 파일 10개(설정 기본값 6, 빈 DB 2, `index.json`, SEC 캐시)가 생기지만 그중 사용자 자료는 없습니다. 이 목록으로 갓 만든 워크스페이스와 쓰던 워크스페이스가 깨끗이 갈립니다.

- 상태 파일이 깨져 있으면 완료로 보지 않습니다. 안내를 한 번 더 보는 쪽이 앱이 안 켜지는 것보다 낫습니다.
- **건너뛰어도 기록합니다.** 다음 실행에 또 띄우면 건너뛰기가 아닙니다.

## 화면 계약

- 배경은 뒤에 떠 있는 앱을 블러 처리한 것입니다. 앱이 비쳐야 "건너뛰면 바로 이거"가 눈에 보입니다. 규칙은 [frontend_ui/DESIGN_SYSTEM.md](../frontend_ui/DESIGN_SYSTEM.md)의 "첫 실행 안내 화면"에 있습니다.
- 위저드는 라우트가 아니라 앱 위에 덮는 한 장짜리 카드입니다. 뒤에 실제 앱이 떠 있어야 건너뛴 순간 바로 쓸 수 있습니다.
- 5단계 — 환영 / 화면 / AI / 관심 시장 / 시작. **어느 단계에서든 건너뛸 수 있고**, 전부 건너뛰어도 앱은 규칙 기반으로 동작합니다.
- **테마는 자기 단계를 갖습니다.** 환영 카드에 얹어 두면 첫 화면이 "이 앱은 무엇인가"와 "무슨 색으로 볼 것인가"를 동시에 묻습니다. 이 단계는 저장 버튼이 없습니다 — 고르는 즉시 반영되므로 `다음`뿐입니다.
- AI 단계는 "AI가 없어도 앱은 그대로 동작합니다"를 먼저 말합니다. 키를 넣어야 쓸 수 있는 도구로 보이면 안 됩니다.

### AI 단계

- 선택지는 `AI 없이` / `CLI`입니다. CLI를 고르면 설치·로그인과 모델을 안내하며 제공자의 인증·요금 정책이 적용됩니다. LLM API 키 입력은 제공하지 않습니다.
- **CLI를 고르면 안내 안에서 설치와 로그인까지 끝냅니다**(`web/src/app/AgentCliSetup.tsx`). 예전에는 "설정 탭의 AI Agent에서 설치와 로그인을 마칠 수 있습니다"라는 문장만 있었는데 **설정 탭에도 그 버튼이 없었습니다** — `POST /api/agent-bridge/install|login`은 구현돼 있었지만 부르는 화면이 저장소에 하나도 없었습니다. 안내가 존재하지 않는 곳을 가리키고 있었습니다.
- 같은 컴포넌트를 설정 탭도 씁니다. 안내가 내내 "나중에 설정에서 바꿀 수 있습니다"라고 말하므로, 설정에서 안 되면 그 말이 거짓이 됩니다.
- 경계 셋을 화면이 먼저 말합니다: 설치는 **Windows에서만**(서버가 `installSupported`로 그렇게 내려줍니다), 로그인은 **별도 콘솔 창**에서(`launch_login()`이 `CREATE_NEW_CONSOLE`), 상태 새로고침은 CLI마다 모델 목록까지 물어 오래 걸립니다.
- 어떤 버튼을 보여줄지는 `web/src/app/agentCliStatus.ts`의 `adapterActions()`가 정합니다. 컴포넌트에서 떼어 둔 이유는 **개발 기계에서 확인할 수 없기 때문**입니다 — CLI가 이미 다 설치·로그인돼 있으면 설치·로그인 버튼이 아예 렌더되지 않습니다. 정작 처음 쓰는 사람만 보는 경로라 테스트가 대신 봅니다.

### 둘러보기 (선택)

- 마지막 단계는 `둘러보기를 진행할까요?`라고 **묻기만 합니다.** 고르면 안내 카드가 닫히고 둘러보기가 **앱 위에서** 돕니다(`web/src/app/AppTour.tsx`, `App.tsx`가 띄웁니다). 카드 안에서 돌면 정작 보여줄 화면이 카드에 가립니다.
- 들르는 곳은 셋입니다: **RSS 피드**(자료가 들어온다) → **시장 내러티브**(이야기가 된다) → **브리핑**(결과물이 된다). 실제로 그 탭으로 이동하고 좌측 내비의 그 자리를 조명합니다. 화면 사용법이 아니라 자료가 지나가는 경로를 말합니다.
- 조명 앵커는 `AppShell.tsx`의 `data-route={route.id}`입니다. 클래스(`.react-left-nav-item`)는 모든 탭이 공유하므로 화면 순서에 기대지 않을 이름이 필요합니다.
- **조명은 오려내기가 아니라 큰 그림자입니다.** 대상 크기의 빈 상자에 `box-shadow: 0 0 0 9999px`를 줘 그 상자만 밝게 남깁니다. `clip-path`는 브라우저마다 다르게 깨지고, 상자는 `pointer-events: none`이라 뒤 화면 클릭을 막지 않습니다.
- **기하를 transition하지 않습니다.** 9999px 그림자를 단 fixed 요소의 `top/left/width/height` 전환은 실측으로 시작값에 갇혀 움직이지 않았습니다 — 조명이 첫 장 자리에 남아 2·3장에서 엉뚱한 곳을 비췄습니다. 같은 이유로 조명과 대체막에 **각자 `key`를 줍니다**: 같은 `div`라 key가 없으면 React가 노드를 재사용해 클래스만 바꾸고, 그 순간 전환이 대상 없는 자리(-20px/0)에서 시작해 그대로 갇혔습니다.
- 대상을 못 찾으면 조명 없이 설명만 가운데 띄웁니다. 좁은 화면에서 좌측 내비가 접혀 버튼이 없을 수 있는데, 그렇다고 둘러보기가 멈추면 안 됩니다.
- 건너뛰면 둘러보기도 하지 않습니다. 건너뛰기는 "지금은 됐다"는 뜻입니다.
- 관심 시장 단계는 기존 `/api/market-scope`를 그대로 씁니다. 저장하면 새로 켠 시장의 수집이 바로 시작됩니다.
- 성공 문구를 남기지 않습니다. 단계가 넘어가는 것이 이미 확인이고, 남기면 다음 단계 아래에 붙어 그 단계를 저장했다고 읽힙니다.
- `aria-modal="true"`를 선언하므로 포커스를 가둡니다(Tab 순환, 단계 전환 시 제목으로 이동, Escape는 건너뛰기).
- 판정을 못 읽으면 안내를 띄우지 않습니다. 쓰던 사람에게 뜨는 쪽이 더 나쁩니다.
- **다시 보기**는 설정 > 자료 위치의 `첫 실행 안내 다시 보기`입니다. 서버 판정을 건드리지 않고 `folio:show-welcome` 이벤트로 화면만 엽니다 — 이미 자료가 있는 사람은 기록을 지워도 `firstRun`이 false라 안내가 뜨지 않고 지웠다는 사실만 남습니다.

## API

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/api/onboarding` | `firstRun`, `completed`, `reason`(`fresh`/`existing_workspace`/`completed`), `completedAt` |
| POST | `/api/onboarding/complete` | `{skipped?: bool}` — 기록 후 갱신된 상태 반환 |

## 주의점

- 저장 위치는 `data/`이므로 [워크스페이스 위치](../common/README.md#workspacepy--workspace_servicepy)를 따라갑니다. 자료를 옮기면 안내 기록도 함께 갑니다.
- 브라우저 저장소를 쓰지 않습니다. 브라우저를 바꾸거나 지웠을 때 쓰던 사람에게 다시 뜹니다.
- 안내를 화면에서 눌러 보며 확인할 때 **완료 버튼을 누르지 마세요.** `/api/onboarding/complete`가 기록되므로, 확인만 할 때는 새로고침으로 빠져나옵니다.
- 안내의 색은 [DESIGN_SYSTEM.md](../frontend_ui/DESIGN_SYSTEM.md) §6을 따릅니다. 눌린 면과 CTA는 **블루가 아닙니다** — 블루는 verdict 칩이 쓰는 의미색이라 UI 액센트로 쓰면 원칙 4를 깹니다. 실측으로 이 화면의 CTA는 `rgb(122,182,234)`인데 앱의 `.btn--primary`는 `rgb(11,12,15)`라 첫 화면만 톤이 달랐습니다.
