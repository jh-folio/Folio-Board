# 내 기준·후보 비교·후보 비중 미리보기 (0.10)

검토에 필요한 자료를 나란히 읽는 개인 층입니다. 매수·매도·보유, 목표가, 권장 비중,
종합 점수나 순위를 만들지 않습니다. `ready_for_review`는 **가격과 내 기준을 검토할
자료가 갖춰졌다는 뜻**이며 기업 전체의 안전성이나 투자 결론이 아닙니다.
이유 미작성·짧은 이유·미검토 이유는 준비 상태 계산의 입력이 아닙니다.

## 내 기준과 준비 상태

- 기존 `valuation_user_criteria` 전역 판본을 재사용합니다. 새 선택 필드는
  `allowAboveHistoricalRange: true | false | null`입니다. DB에는 `allow | disallow | NULL`로 저장합니다.
- 기존 저장 요청이 선택 필드를 생략하면 현재 값이 유지됩니다. 명시 `null`은 선택 기준을 지웁니다.
  기존 세 숫자 필드의 전체 저장·판본 충돌 계약은 유지합니다. 편집 위치는 설정 → 관리 하나입니다.
- 읽기는 이전 DB의 열을 만들지 않습니다. 명시 기준 저장/기존 가격 저장의 schema 준비에서만
  백업·잠금·트랜잭션으로 v2 열을 추가합니다. 이전 판본·가격 입력·결과는 수정하지 않습니다.
- 높은 전제 기준은 보유기간의 성장·끝 PER·순이익률 별도 역산을 과거 표본 최고값과 비교합니다.
  각각 최소 3/5/5개, 엄격한 `>`만 범위 초과이며 p75는 경계가 아닙니다.
  PER `not_needed`도 유효 표본이 필요합니다. 탐색 범위 밖은 과거 범위 초과로 바꾸지 않습니다.
- 우선순위: 지원/방법/자료 무결성 미확인 `unknown` → 오래됨/정정 `stale` → 확인된 기준 미달
  `criteria_unmet` → 필수 계산 부재 `incomplete` → 필수 기준 미확인 `unknown` → `ready_for_review`.
  필수 범위는 기본 시나리오와 판정 가능한 DCF·요구수익률·최소 안전마진·보유기간입니다.
  선택 기준은 정했을 때만 필요합니다. 기업 품질·거시·지난 수익·Portfolio·내 이유 공백은 따로 남깁니다.

## 읽기 API와 재현

| 경로 | 역할 |
|---|---|
| GET `/api/decision-readiness/{instrumentId}` | 현재 또는 지정 가격/기준 판본의 준비 상태와 맥락 |
| POST `/api/opportunity-comparison` | 선택 순서의 최대 8개 후보, 7항목과 항목별 비교 불가 사유 |
| POST `/api/portfolio/decision-preview/basis` | 명시 요청 때만 보유 시세·환율과 후보 분류를 읽어 서버 메모리에 고정 |
| POST `/api/portfolio/decision-preview` | 고정 기준과 사용자가 적은 최종 비중으로 순수 계산 |

응답 규칙은 `decision-readiness-1` / `decision-readiness-rules-1`입니다.
가격 방법 1~5의 알려진 지문만 읽으며 기존 가격 계산 방법과 지문은 올리지 않습니다.
US/KR/JP/EUROPE 시장과 증권 식별을 유지합니다. 발행회사 CIK만으로 보통주·ADR을 합치지 않습니다.

비교 재생에는 응답의 `evaluatedAt`과 `referenceSet`을 함께 보냅니다. 가격·개인 기준·이유 판본,
이유 검토 이벤트·가격 정정 행의 ID/내용 해시, 기업분석 ID/파일 해시, 공시 노출 판본,
거시 관측 상한/행/메타데이터 해시, 가격 계산 실패 기록의 해시 또는 부재,
Portfolio 원문 해시를 고정합니다. 빈 검토 목록과 입력 부재도 고정됩니다.
이후 추가된 검토/정정/판본은 당시 결과에 섞지 않습니다. 바뀐 파일·유실·요청 중 입력 변경은 409입니다.
잘못된 요청은 422, 읽기 장애는 503으로 알리며 0이나 기본 통화로 메우지 않습니다.

비교의 숫자는 기준일·통화·방법/규칙 지문·기간·숫자의 정의가 같을 때만 같은 기준으로 표시합니다.
ETF·미지원 시장·오래된 가격 자료는 해당 칸을 제한하며 다른 항목은 남깁니다.
이유 저장소의 기존 ticker 정규화를 재사용하며 시장/거래소를 확인할 수 없는 이름은 이유·검토를 unknown으로 남깁니다.
다른 시장의 같은 ticker에 기존 이유를 붙이지 않습니다. 손상된 보고서는 부재로 숨기지 않고 해당 칸과 고정 해시의 읽기 장애를 표시합니다.
기업 품질은 기존 보고서의 재무 품질·경쟁우위·리스크 원문 일부이며 보고서 생성 품질 점수를 쓰지 않습니다.
과거 수익은 기존 0.9.2 저장 입력으로만 읽고 미래 연 수익률과 섞지 않습니다.
`portfolioBasisId`가 있으면 확인된 현재 겹침 비중을 연결합니다. 없으면 정확한 보유 여부/분류와 비중 미확인 사유를 보여 줍니다.

## Portfolio 계산 경계

`portfolio.json`을 원문으로 읽고 기존 평가/환율 캐시 작성 함수를 호출하지 않습니다.
시세는 기존 Yahoo chart 제공자의 실제 symbol·통화·단위를 확인합니다. 이전 종가/임의 USD로 대체하지 않습니다.
보유 ticker·시장과 제공자 symbol의 동일 증권을 먼저 확인합니다. 다른 증권의 symbol을 대입하지 않으며 별도 해외 거래소 상장선을 합치지 않습니다.
모든 보유의 수량×시세×환율과 명시 현금을 USD 분모에 포함합니다. 하나라도 확인할 수 없으면 전체 비중 불가입니다.
후보 자체 가격은 필요하지 않습니다. 후보 분류는 같은 증권의 저장 가격 입력/보유 행에서만 읽습니다.

후보의 **최종 비중**을 `w`, 기존 후보 비중을 `b_c`라고 하면 다른 자산·현금은
`b_i × (1-w)/(1-b_c)`입니다. 0과 미입력은 다릅니다. 후보만 있는 구성에서 100% 미만으로
바꾸면 `no_other_assets`입니다. 실제 Portfolio를 저장하거나 거래 수량을 계산하지 않습니다.

공시 요인+방향의 확인된 보유 비중을 증권당 한 번만 합산합니다. 여러 그룹은 겹치며 전체 위험률이 아닙니다.
산업/시세 통화와 매출 통화는 구별하며 미조사 비중을 별도로 표시합니다. 현금은 분모에 들어가지만
보유 종목 최대/상위3/5 집중도에서는 제외합니다. MMF·단기채 ETF를 현금으로 바꾸지 않습니다.
펼친 공시 근거에는 원문 인용·공시일·profileId·정성/회사 수치 설명을 함께 남깁니다.

ETF의 확인 구성 묶음은 순수 계산에서 출처·구성일·실제 비중·증권 식별을 검증한 부분만
`ETF 비중 × 구성 비중`의 별도 표로 보여 주며 직접 비중과 중복 합산하지 않습니다.
현재 Portfolio/0.8 저장소에는 검증된 구성 묶음의 소유 기능이 없어 실제 읽기에서는 구성 미조사입니다.
새 구성 수집기나 추정은 없습니다. 저장 백테스트는 기존 화면에서 읽을 수 있지만 원입력·현금·후보 구성·기간의
완전 일치를 확인하지 못한 결과를 후보 후 위험 기여 숫자로 재사용하지 않습니다. 새 위험 계산을 하지 않습니다.

기준은 30분, 현재 workspace, 최대128묶음의 서버 메모리 안에서만 유효합니다. Portfolio 원문 변경·만료는 409입니다.
브라우저의 후보 선택/비중 초안은 메모리에만 있으며 화면 이동 동안 유지됩니다. 새로고침에서 초안이 소멸하고 서버 재시작에서 시세 기준이 소멸합니다.
비교 저장·결정 스냅샷/이력의 저장 위치를 새로 만들지 않습니다(0.11 인계 대상).

## 검증과 한계

`tests/`는 손계산·빈/일부 기준·이유 길이 독립·기간/통화 차이·ETF·미지원·오래됨·일부 공시 노출,
고정 판본 재생·요청 중 변경·읽기 보존·기준 열 추가를 합성 자료로 검사합니다.
화면 검사는 `web/tests/e2e/decision-readiness.spec.ts`와 기존 `price-tab.spec.ts`입니다.
자동 검사와 임시 자료 흐름은 실제 개인 자료의 실사용 확인을 대신하지 않습니다.
상태 문구의 이해·비교의 유용성·계산 가정의 이해·이유 작성량에 대한 실제 수용은 1.0 후보 테스트로 이월합니다.
