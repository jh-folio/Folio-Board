# 가격 시나리오

가격 시나리오는 외부 공시와 완결 거래일의 종가를 입력으로 삼는 규칙 계산이다.
개인 투자 이유·대화·사용자 가정을 정본의 근거로 쓰지 않는다.

가격 시나리오는 워치리스트 기업 상세의 `가격` 탭, 기업분석 보고서, Agent 컨텍스트가 같은
저장된 스냅샷 하나를 읽습니다. 계산은 명시적인 `계산` 동작과 기업분석 생성 때만 하며, 읽기는
수집·계산·저장을 하지 않습니다. 확률·목표가격·매수/매도 지침은 만들지 않습니다.

0.9.1의 계산 범위 보강은 다음과 같습니다.

- 최근 주당이익이 0 이하인 경우와 짧은 기록·적자 해·빠진 공시 값을 구별해 안내합니다.
  ETF·펀드는 별도 안내를 합니다. 미국 회사 식별 실패 때만 짧은 종류 조회를 하고,
  펀드를 확인하지 못하면 SEC 공식 펀드 목록의 정확한 종목 코드를 추가 확인합니다.
  정상 회사에는 이 추가 조회가 없습니다. 제공처의 통신 오류도 원인에 맞게 표시합니다.
- SEC의 과거 주당이익이 빠진 해는 같은 해 순이익과 희석 주식 수로 검산을 거쳐
  최대 두 해만 채웁니다. 최근 기준 연도는 채우지 않으며 출처·검산 값은 저장합니다.
- 비자처럼 종류별로 공시하는 회사는 최근 연차보고서 최대 여덟 건에서 상장 종류의
  실제 주당이익·주식 수를 읽습니다. 검산한 최신 해를 포함해 세 해 이상이 필요하며,
  주식 종류·통화·사건·업종 제한은 그대로 적용합니다. 10년 창을 덮으면 일찍 멈춥니다.
  숫자 없는 정정 공시는 건너뛰되 여덟 건에 포함합니다. 인라인 형식이 아닌 원본이나
  형식 문제가 나오면 그 지점에서 멈추며 10년 확보를 보장하지 않습니다.
  필요한 공시의 통신 실패는 이번 계산 전체를 중단하고 이전 저장 결과를 유지합니다.
- 수익률 여섯 행이 모두 적자 또는 짧은 기록으로 막힐 때만 가격 탭에
  ‘수익률 대신 볼 수 있는 숫자’를 보입니다. 지금 PER·매출 대비 주가·최근 현금 비율과
  연도별 기록을 표시하고, 없는 값은 사유를 적습니다. 이전 해나 숫자 0으로 대신하지 않습니다.
  이 참고 숫자는 보고서·보고서 응답·CLI 생성 문맥·개인 기준 비교에 넣지 않습니다.

`coverage_history.py`·`class_history.py`는 사건 보정 전 원값 이력을 보강합니다.
보강 출처는 `inputs.history`에 저장하여 캐시나 네트워크 없이 재생할 수 있습니다.
`reference_facts.py`의 배수는 보정한 주당 값만 쓰고, 전사 매출·이익·현금은 공시 원값을 씁니다.
입력 지문에는 `specSha256`을 포함합니다. 출처 보강 자체는 공시 정정으로 표시하지 않으며,
비교할 수 있는 실제 원천 공시가 바뀐 경우에는 이전 기록과 참조 보고서의 재검토 안내를 유지합니다.
기존 기록·이전 명세 사본은 수정하지 않습니다.

- `history.py`: SEC 원자료의 기간별 태그 선택·최신 공시/이전 값·최대 10년,
  DART 당기/전기/전전기와 동일 연결 기준을 보존한다. 기존 보고서 요약을 바꾸지 않는다.
  DART 기말은 별도 원자료에서 확인한 `periodEnd`를 반드시 전달한다.
  보통주 배당은 `alotMatter`의 원/주 값을 읽고 우선주·결측·숫자 0을 구별한다.
- `securities.py`: SEC 표지의 정확한 ticker/context와 각주에서 상장증권 종류를 읽는다.
  20-F만으로 ADR을 판정하지 않고, ADS 비율·공시 주당 기준을 못 확인하면 제한한다.
- `support.py`: 공식 업종·상장증권 종류·통화·주식 단위 제한을 먼저 적용한다.
  종류 미확인에서는 기존 단위 함수의 compatible 결과로 주당 계산을 열지 않는다.
- `prices.py`: 미국/한국 종가 완결 시각과 진행 중 세션·stale을 확인한다.
  거래소는 공식 메타데이터로 정하고 한국 `.KS/.KQ` 순차 추정은 하지 않는다.
  `fetch_daily_history()`만 명시 조회를 수행한다. 11년 일봉의 `auto_adjust=False`
  종가와 공급자 사건을 수집하고 장중 가격·배당 조정 가격·기존 앱 캐시를 쓰지 않는다.
- `events.py`: 출처 간 사건을 한 번만 합치고 로그 거리로 가격 반영을 확인한다.
  공시 이후 사건만 주당 값/주식 수에 반영하고 검증된 ADS 비율을 마지막에 적용한다.
  한국 기말 주식 수는 `korean_shares.py`의 공식 단위 증명/기말 단위 잔차로 대조한다.
  spec-1의 두 단위 구간 계산은 `reconcile_korean_shares_v1`에 재현용으로 보존한다.
  빈 사건 목록만으로 `none_confirmed`를 반환하지 않는다.
- `sec_events.py`: 같은 기간의 희석 주식 수·EPS를 공시별로 짝짓고 모든 공시 짝을
  사건 배율의 곱과 대조한다. 일반 정정·누락·사건 출처 실패를 구별한다.
  공시 앞뒤의 예상 분할 흔적이 없으면 `unknown`이다. ADR의 공통주 흔적과 맞지 않는
  공급자 사건은 `ads_ratio_change`로 두되, 최신 20-F 이후 사건은 `unknown`이다.
- `dcf_history.py`: 같은 10년 이력에서 기존 DCF 독자가 읽는 연간 항목을 만든다.
  실제 기말·누락·0·공시 ID·주식 수 환산 출처를 보존하고 같은 FY의 모호한 값은 거부한다.
  이 어댑터 자체는 지원 여부를 확정하거나 DCF를 실행하지 않는다.
- `dart_events.py`: 무상증자 결정의 신주 배정비율에 1을 더하고 기준일 직전 거래일과
  예정 상장일을 구분한다. 연간 증감 공시의 날짜별 유상증자·전환·감자를 읽으며,
  미확인 종류·불완전 자료는 빈 목록으로 바꾸지 않는다. 예정일은 집행 확인과 다르다.
- `korean_shares.py`: spec-2의 이익소각/상환 누적 원값과 항목별 공식 단위 증명,
  사건 범위·당일 단위 순서를 보존한다. 같은 기말 단위로 환산해 잔차를 계산하며
  미확인 단위·상환 결측·정정/누적 감소는 unknown이다. DART의 `-`는 0이 아니다.
  원입력만 지문에 넣고 환산계수/잔차는 결과에 둔다. 이전 spec-1 결과는 바꾸지 않는다.
- `debt_inputs.py`: 확인된 연간 기말의 차입금·현금·개별 계정 출처를 묶는다.
  결측 부채를 0으로 채우지 않고 부분 포지션은 부분으로 표시한다. IFRS 차입금의
  유동성 부분 포함 여부는 공식 정의 근거가 있을 때만 사용한다.
- `dcf_runtime.py`: 조정된 주식 수·기준 가격·시가총액·FCF·성장 관측·금리·beta·
  세율·차입 비용·부채·말기 성장률을 포착하고 기존 10년 DCF 엔진으로 재현한다.
  지원 제한을 먼저 확인하고, 성장/할인율 대체값이면 안전마진 판정은 unknown이다.
- `decimal_ops.py`: 유한 Decimal 입력·원천 정밀도·정규 inputs SHA-256을 관리한다.

순수 입력 함수는 전달받은 원자료만 사용하며 캐시·개인 DB 쓰기를 하지 않는다.
실자료 확보·필드 해석과 입력 fixture 통과는 저장/보고서/UI 수용과 구분한다.

DCF 공통 성장률은 `company_analysis/dcf.py`가 실제 회계연도 간격을 사용한다.
같은 폴더의 `risk_free.py::risk_free_as_of()`는 기준 종가 날짜 이하 관측을
FRED→Yahoo→상수 순서로 선택하고 원관측 단위와 출처를 반환한다. 가격 계산 수집(`collect.py`)이
이 값을 읽어 스냅샷 입력에 넣으며, 기존 최신 금리 조회/캐시와는 별도다.

입력 수용은 끝났다. 한국 사건의 집행일·증감/소각 단위 대조(spec-3 표 산술 읽기), beta 측정, 입력 전부의 영구
저장(지문), 공통 생성 경로 연결은 아래 "계산·저장·연결"에 있다. 누적 소각 단위가 분할 전후에 달라 잔차로
설명되지 않는 사례는 `unknown`을 유지하고, 값을 임의 보정하거나 단위 검증 완료로 표시하지 않는다.

## 계산·저장·연결 (기존 계약)

- 계산(순수): `stats.py`(type 7 백분위), `returns.py`(IRR·역산), `ranges.py`(과거 범위),
  `decomposition.py`(성장 분해), `scenarios.py`(저장되는 결과 조립). 새 계산은 Decimal이며
  저장 직전에 한 번만 반올림합니다. 범위를 벗어난 해는 숫자로 자르지 않고 `above_range`/`below_range`입니다.
- 베타(`beta.py`): 조회 시점 값을 출처와 함께 입력으로 저장합니다(제공자는 관측일을 주지 않으므로
  조회 시각은 지문 밖). 없거나 이상하면 측정 안 됨이며 DCF는 대체값, 안전마진은 `unknown`입니다.
- 저장(`store.py`): `market-memory.sqlite3`의 불변 테이블 `price_snapshots`·`price_snapshot_links`·
  `price_snapshot_reviews`와 개인 층 `valuation_user_criteria`·`valuation_assumption_overrides`.
  UPDATE/DELETE는 트리거로 막고, 스냅샷·대체 링크·재검토 행은 한 트랜잭션입니다. 같은 지문의 다른 결과는
  `non_reproducible`로 거부합니다. 첫 migration 전 SQLite backup을 만듭니다. 읽기는 파일·테이블을 만들지 않습니다.
- 변경 이유(`changes.py`): 직전 스냅샷과 입력을 비교해 `price_moved`·`new_fiscal_year`·`restated`·
  `share_event_added`·`dcf_assumption_changed`·`method_changed`·`input_changed`를 적고, 정정된 값을 쓴
  모든 이전 스냅샷에 재검토 행을 남깁니다.
- 읽기 투영(`projection.py::project`): 기준 판정(기본 시나리오만)·요구수익률 역산·내 가정 수익률·재검토·경과 안내를
  쓰기 없이 계산합니다. 모든 소비자가 이 함수를 부릅니다.
- 수집·조립(`collect.py`, `assemble.py`): 수집만 외부 호출을 하고 조립은 순수합니다. 보고서와 화면의 숫자는 같은 스냅샷에서 옵니다.
- API(`routes.py`, 접두사 `/api/price-snapshots`·`/api/valuation`): `POST calculate`(SharedJob `price_scenario`,
  종목당 한 번에 하나), 스냅샷·이력·투영 조회, 전역 투자 기준과 종목별 내 가정(append-only, 기대 revision이 다르면 409).
- 보고서 연결(`report.py`, `report_link.py`): 새 보고서는 `priceSnapshotId`만 가리키고 PER 시나리오·DCF를 스냅샷에서 읽으며,
  ×0.7/×1.3 표·"현재가 대비" 열·두 번째 DCF는 만들지 않습니다. 현재 배수 표(PER·PSR·EV/EBITDA·FCF 수익률 등)는 그대로 둡니다.
  보고서를 열 때 그 스냅샷이 정정으로 재검토 대상이 되었으면 응답에만 `priceReview`를 실어 안내합니다(저장된 보고서는 바뀌지 않음). 스냅샷을 만들 수 없으면 사유와 함께 id 없이 생성합니다.
  제공자는 앱 시작 때 등록되며(`set_price_snapshot_provider`) 등록이 없으면 예전 경로가 그대로 동작합니다.

알려진 한계: SEC companyfacts로는 주식 종류별 주당이익 차이를 판정하지 못합니다. 한국 주식 수 대조는 명세 spec-3
(표 산술 읽기, `korean_table.py`)을 쓰며, 증감 원장이 설명하지 못하는 발행(예: 합병 신주)이 있으면 그 종목은
`share_event_unknown`입니다. 한국 주식 수 표 원값·증감 원장·coverage는 `inputs.shareEventSources.krShareCounts`에 저장되어
지문에 들어갑니다.

판정 비교는 저장된 반올림 값(성장률 4자리·PER 2자리·수익률 4자리)으로 합니다. 저장 직전 한 번 반올림한다는 원칙의
알려진 예외이며, 실제 9.996%가 `0.1000`으로 저장되어 10% 기준을 충족으로 읽을 수 있습니다. 가격이 오래됐는지는
UTC 날짜 기준 평일 수로 세므로 거래소 현지 날짜와 최대 하루 어긋날 수 있습니다.

## 교차 확인 (0.9.1, spec-4)

0.9.1의 계산은 `price-scenario-4` / `price-scenario-spec-4`입니다. 기존 수익률·DCF·판정은 유지하고 설명용 세 항목을 더합니다. `crosschecks.py`가 Decimal 계산을 소유합니다.

- **수익률의 세 조각**(`results.returnParts`): 보수·기본·낙관 × 5·10년의 6행입니다. 같은 반올림 전 가정으로 현재 PER이 유지될 때의 IRR을 구하고, 성장 + 배당 + PER 변화의 저장값 합이 기존 저장 IRR과 정확히 같게 합니다. 개인 가정에는 적용하지 않습니다. 범위 밖 해는 `irr_above_range`·`irr_below_range`·`flat_irr_out_of_range`로 남깁니다.
- **성장 없는 가치**: 최신 회계연도 주당 매출 × 반올림 전 과거 순이익률 중간값을 `results.noGrowth`에 저장합니다. 개인 요구수익률을 적용한 값은 가격 탭의 `project().noGrowth`에서만 계산합니다. `requiredReturn`은 4자리 소수 비율이고 `criteriaRevisionId`를 함께 반환합니다. `hasGrowthShare`는 반올림 전 가격 설명 비율이 1 미만인지를 전달해 표시 문장이 반올림 경계에서 바뀌지 않게 합니다. 이 항목은 보고서 본문·응답·CLI 문맥에 포함하지 않으며 판정을 바꾸지 않습니다. 기준 미설정·0 이하 요구수익률은 각각 `criteria_not_set`·`required_return_not_positive`입니다.
- **이익이 현금으로 남았나**(`results.cashConversion`): 공시 원본의 같은 연도 순이익·영업현금·자본지출을 최대 10년 합산합니다. 5개 연도 이상, 합산 순이익이 양수일 때 비율을 만듭니다. 자본지출은 절댓값, SEC 주식 보상 비용은 대상 연도 전부에 있을 때만 원래 부호로 차감합니다. 일부 결측이면 전부 미차감, 한국은 별도 미차감 안내입니다. `supported`·`limited`에 적용하고 주당 사건·주가 통화와 무관하게 **공시 통화**를 표시합니다. 공시가 오래돼도계산하되 안내를 붙이며, 비율 불가 시에도 연도별 값·합계를 남깁니다. 분류는 반올림 전 비율의 0.80·1.50 경계, 문장의 100당 금액은 저장 4자리 비율에서 half-even으로 표시합니다. DCF 현금 정의 및 지배주주 순이익/연결 영업현금의 범위 차이에 주의합니다.

가격 탭(`web/src/app/price/`)은 위에서 아래로 **결론 → 참고 숫자(해당 종목만) → 한눈에 보기 → ① 얼마를 벌 수 있나(A · 가정별 수익률) → ② 지금 가격이 무엇을 가정하나(전제 · B) → ③ 과거 기록은 어땠나(성장 분해 · C) → 접기 목록(연도별 현금 근거 · 내 가정 · 근거와 출처) → 계산 기록** 순서입니다. 주당 계산이 제한된 종목은 C만 단독으로 보이며 연도별 표를 그 안에 접어 둡니다.

수익률이 한 칸도 계산되지 않은 지원 종목(범위 밖 수익률은 계산된 것으로 봄)은 결론 영역에 이유만 두고 카드·막대·보유 기간·한눈에 보기·①② 묶음을 그리지 않습니다. 그 아래에는 참고 숫자(해당 시), 계산된 경우의 성장 분해와 C, 근거와 출처, 계산 기록만 이어집니다. 내 가정 계산도 기본 시나리오가 없으면 결과를 낼 수 없어 숨깁니다. ETF·펀드처럼 스냅샷 없이 `fund_not_supported`로 끝난 경우에는 결론 영역이 직접 "이 종목은 이 계산의 대상이 아닙니다"라고 말하고, 첫 계산 안내와 실패 배너를 함께 띄우지 않습니다.

- **결론 문장**은 확정적으로 말하지 않습니다: "과거 10년 흐름이 이어진다면, 지금 사서 N년 보유할 때 연평균 X%입니다." 둘째 줄이 내 기준 비교이고, 비교는 기본 보유 기간으로만 합니다. 설명은 과거 사실(주당이익 성장·보통 PER)을 먼저 쓰고 "보장된 수익이 아닙니다"를 붙입니다.
- **한눈에 보기**는 아래 계산을 다섯 줄로 요약하고 각 줄 끝에서 해당 섹션으로 옮겨 줍니다(해시 라우터라 `#id` 링크 대신 `scrollIntoView`). 판정이 아님을 마지막 줄에 적습니다.
- **섹션 틀**(`Guide.tsx`의 `GuideSection`): 제목 → 이 섹션이 답하는 질문 → 내용 → `계산`(실제 숫자로 쓴 식) → `이렇게 보세요`.
- **클릭은 설명이 늘어나는 곳에만** 둡니다: 결론 카드(시나리오 선택), A 조각 카드(그 조각만 막대에 남기고 설명), 전제 줄(계산 방법 펼침, Enter·Space 포함), 성장 분해 카드. B·C 카드와 표 행은 누르지 않습니다.
- **A 표시 규칙**: 수익률·성장·배당·PER 그대로 수익률은 소수 1자리로 반올림해 보이고, PER 변화는 화면 수익률 − 화면 성장 − 화면 배당으로 보여 화면 숫자의 합이 맞습니다. PER이 내려가는 몫은 막대의 빗금입니다.
- 보유 기간(5·10년)을 바꾸면 결론·카드·막대·표 강조 열·전제 줄(펼친 설명 포함)·한눈에 보기·A가 함께 바뀝니다. C 금액은 짧은 표기(억 달러·조 원)입니다. 보고서·CLI·`scenario_payload`는 **기본 5·10년 A와 C만** 더합니다. 이전 방법 1~3의 A·C는 조회 응답에서 단일 `not_applicable(previous_method)` 블록, B는 투영에서 같은 사유를 반환합니다. 저장 본문은 바꾸지 않습니다. spec-3 이후 방법끼리 정정 검토는 계속 연결하고, 서로 다른 방법 사이에서는 SBC만 비교에서 제외합니다.

IFRS SBC 태그는 이 기능 안에서 `AdjustmentsForSharebasedPayments`를 우선하며 공용 후보 표는 유지합니다. 기존 회계연도·제외 연도·다른 지표를 보존합니다. 한국의 영숫자 6자리 종목코드도 수집·가격 제공자·화면에서 받습니다. 보고서 취소는 가격 수집/저장 경계까지 전달되고, 화면이 숨겨지거나 해제되면 계산 상태 조회를 멈춥니다.

## 주가 수익의 출처 (0.9.2, spec-5)

새 계산은 `price-scenario-5` / `price-scenario-spec-5`입니다. SHA-256은 `3015c60574c65a621d1ba90841540095b324858203631698003185eb90fb0184`입니다. 방법 1~4의 저장 결과와 알려진 동결 지문은 계속 읽으며, 기존 0.9·0.9.1 결과 블록은 변경하지 않습니다. 알 수 없는 방법·지문으로 새 투영이나 정정 비교를 하지 않습니다. SBC 비교 제외는 spec-3↔4·5 사이에만 적용합니다.

- **가격 탭 ③ 첫 섹션**은 1·3·5년(기본 5년)의 과거 누적 수익을 설명합니다. 최근 확정 회계연도 말과 N년 전 회계연도 말의 가격·공시 주당이익을 짝짓습니다. 휴장일이면 그 이전 완료 종가를 최대 10평일 안에서 선택하고 실제 날짜를 보입니다. 오늘 가격을 쓰는 미래 시나리오의 `peNow`와는 다른 기간입니다.
- **세 조각**은 이익 성장, PER 변화, 배당입니다. `P1/P0−1 = (E1/E0−1) + PER 변화`이며, 함께 변한 효과는 PER 몫에 넣는 계산 순서입니다. 인과 설명이 아닙니다. Decimal 28자리·half-even을 쓰며 수익률 4자리에서 PER 몫을 차이로 계산합니다. 연평균 미래 IRR과 혼동하지 않습니다.
- **화면 표시**(표시 보충 1, 2026-10-05 사용자 확정 — 계산 값은 그대로): 누적 덧셈 %p는 큰 움직임에서 읽히지 않으므로(예: 이익 +2,782%p·PER −1,961%p) 화면의 주 표시는 **배수**입니다.
  - 첫 문장: 주가 수익(×배수)과 사실 결론 한 줄. 예: '주당이익은 늘었지만 PER이 낮아져, 이익이 늘어난 만큼 오르지는 못했습니다.' 결론은 배수의 로그 크기로 어느 쪽이 컸는지만 말하고, 변화 10% 미만은 '거의 그대로'로 씁니다. 원인은 단정하지 않습니다.
  - 카드: 주당이익·PER 각자의 변화율(예: +2,732%, 75.1배 → 38.3배 −49%)과 받은 배당(시작 주가 대비). 누르면 설명이 나옵니다.
  - 배수 막대: ×1 기준선을 가운데 둔 로그 눈금. 주당이익·PER, 구분선 아래 결과(주가)와 시장지수(회색). 기준선 쪽은 직각, 바깥 끝만 둥급니다. 색은 ① 수익률 세 조각과 같습니다(이익 파랑·배당 초록·PER 빗금).
  - 계산 상자: 곱셈식, 배당 포함 전체 %, 덧셈 %p(합계 규칙 그대로), 배당 제외 시장 비교.
  - 그 뒤 한 줄: 기간 끝(회계연도 말) 다음부터 저장 기준일까지의 주가 변화를 저장 입력(`/api/price-movement`, 분할 반영)으로 한 줄 보입니다. 나누지 않습니다.
  - 이익과 PER로 나눌 수 없으면 카드를 그리지 않고 주가·시장지수 막대만 보입니다. 수익률이 없는 종목에서는 ③ 번호 머리를 홀로 두지 않습니다. 한눈에 보기에는 같은 형식의 한 줄을 더합니다.
- **배당**은 실제 계좌 수령액이 아니라 제공자 배당락일 기록 `(시작 종가일, 끝 종가일]`의 세전 현금배당입니다. 재투자·수수료는 포함하지 않습니다. 원 Close/Adj Close의 변화로 배당 주식 단위를 상대오차 1% 안에서 확인하고, 확인된 미반영 분할만 한 번 환산합니다. 당일 분할·모호한 단위·미확인 ADS 단위는 배당 불가입니다. 빈 성공 기록은 ‘제공자 기록상 배당 없음’, 실패는 0이 아닙니다.
- **시장 비교**는 배당을 뺀 종목 가격 수익과 같은 실제 날짜의 S&P 500/KOSPI 가격지수입니다. KOSDAQ도 KOSPI와 비교합니다. 종목의 배당 포함 전체 수익은 별도 표시하며, 지수 날짜를 앞뒤로 채우지 않습니다. EPS가 0 이하이면 이익/PER만, 배당 실패이면 배당/전체만, 지수 실패이면 지수만 제한합니다.
- **입력 보존과 읽기**: `attribution.py::capture`는 기존 inputs에 `returnAttributionInputs`만 추가합니다. 명시 계산의 종목 일봉·배당 원값/단위/날짜 근거·조정종가·주식 수 사건·지수 일봉·제공자 버전/요청 조건/자료 상태가 기존 지문에 포함됩니다. 조회 때 `historical_attribution`/`movement`는 이 입력만으로 계산합니다. 조회·기간 변경·묻기에서 외부 수집/새 snapshot/새 분석 객체를 만들지 않습니다. 이전 기록에 새 입력이 없으면 다시 계산 안내를 보입니다.
- **기업 정보 차트**의 ‘이 움직임 물어보기’는 명시 클릭만 Agent를 실행합니다. 날짜 하나를 고르면 그날부터 마지막 완료 거래일, 고르지 않으면 차트 구간을 요청합니다. 비교 입력 기준일·요청/실제 날짜·확인된 차트 종가 차이를 알립니다. 서버는 고정 snapshotId와 선택 날짜로 사실을 다시 읽고, 클라이언트 수익률을 받지 않습니다. 대화는 hypothesis·`reuseAsEvidence=false`입니다. 입력이 없으면 가격 탭 이동과 불가 사유만 전달합니다.
- **기준일 이후 네 축 변화 비교**는 선택 날짜·시장으로 기존 거시 화면을 엽니다. 기존 월별 저장 기록을 읽는 방식이며 새 계산·수집은 없습니다.
- **공시 오류**는 실제 HTTP 상태로 구분합니다. 404/410은 자료 없음, 401/403은 접근 제한, 확인된 408/429/5xx·통신 실패만 일시 오류입니다. 진단이 없는 이전 문자열은 중립 문구로 읽습니다. 필수 원문 실패에서 계산 전체 중단·이전 결과 보존은 그대로입니다. 오래된 원문 캐시가 있어도 새 계산 성공으로 바꾸지 않습니다.

과거 수익 섹션은 보고서 본문·보고서 응답·생성 CLI에 자동으로 추가하지 않습니다. 차트의 명시 클릭으로 넘긴 사실만 Agent 대화 문맥에 들어갑니다. 독립 단위/HTTP 검사는 `tests/test_attribution.py`, 화면 검사는 `web/tests/e2e/price-tab.spec.ts`·`macro-state.spec.ts`를 사용합니다. 실제 공개 자료·고정 표본 회귀·임시 환경 흐름·독립 리뷰 증거는 개인 개발용 계획 폴더에 보존합니다.
