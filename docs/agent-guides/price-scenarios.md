# 가격 시나리오 (가격 탭·투자 기준)

> 이 기능을 변경·검토할 때 [features/price_scenarios/README.md](../../features/price_scenarios/README.md)와 함께 읽는다. 다른 기능의 상세 문서를 일괄 로드하지 않는다.
> 공통 규칙과 § 번호는 [AGENTS.md](../../AGENTS.md)를 참조한다. 코드 경로 표기는 저장소 루트 기준이다.

### 가격 시나리오 (0.9.2)

- **현재 새 계산은 spec-5**(SHA-256 `3015c60574c65a621d1ba90841540095b324858203631698003185eb90fb0184`)입니다. 사용자 승인 F+E+S: 과거 회계연도 말끼리, 배당락일 세전·미재투자, 명시 계산 때 종목/배당/지수 원입력 보존 후 순수 읽기 계산입니다. 자세한 입력·표시·불가 규칙은 기능 README의 ‘주가 수익의 출처’를 따릅니다. 아래 spec-4 계약은 기존 결과의 보존 기준입니다.
- **0.9.2 A~D**: 가격 탭 ③의 과거 수익 출처(화면 주 표시는 배수: 주당이익 × PER = 주가, 누적 %p는 계산 상자)와 배당 제외 지수 비교; 기업 정보 차트 명시 클릭의 고정 snapshotId·선택 기간 사실을 Agent에 전달; 선택 날짜의 기존 월별 거시 비교 링크; 실제 HTTP 상태에 따른 공시 오류 문구입니다. 기존 연평균 IRR·DCF·판정은 그대로이며 A는 보고서/생성 CLI에 자동 추가하지 않습니다. Agent 대화는 hypothesis·reuseAsEvidence=false입니다.
- **읽기에는 수집·쓰기가 없습니다.** `/api/price-movement`·snapshot의 `attributionYears=1|3|5`는 저장 inputs만 씁니다. 미확인 분할/배당/지수는 해당 블록 불가이고 0 또는 다른 날짜로 대신하지 않습니다. 새 입력 없는 이전 기록은 재계산 안내입니다. 방법 1~4의 알려진 SHA 읽기와 저장 본문을 보존하고, 알 수 없는 방법/SHA는 새 계산/정정 비교에서 제외합니다. spec-3↔4·5의 SBC만 정정 비교에서 제외합니다.

- **계산 방식은 동결 명세가 정한다.** 현재 동결 기준은 `price-scenario-spec-4` 개정 1 E3 읽기 범위 보완(전체 SHA-256 `083085f1425d2db29286c3b01fb59ce9b5a0356affd45420803cfe8d86f35773`)이다. 기존 계산·판정은 spec-3과 보충 해석을 유지하되 개정 1의 E1 사유와 E2/E3 공시 입력 보강에서 직접 생긴 변화만 허용한다. E4 참고 숫자는 판정·보고서·CLI 입력이 아니다. 원래 개정 0 SHA `67cea923…d6aa`와 초기 개정 1 SHA `9e88a0ab…8f1a`·SEC 펀드 보완 SHA `b249c6dc…c567` 및 저장본은 읽기 호환을 유지한다. 새 설명용 A·B·C와 상태/정밀도 계약은 기능 README를 따른다. 계산·판정 의미를 바꾸려면 명세 변경 → 사용자 승인 → 독립 리뷰 → 새 동결 지문을 거친다. 동결 본문은 고치지 않는다. 명세 파일은 개인 개발용 로컬 계획 폴더에 있어 공개 저장소에는 없다.
- **두 층을 섞지 않는다.** 스냅샷(정본, 입력 지문 고정, `market-memory.sqlite3`의 불변 표)과 개인 층(투자 기준·내 가정, append-only)은 읽을 때 `project()`가 합친다. 개인 층은 스냅샷·보고서·Thesis·포트폴리오를 바꾸지 않는다.
- **같은 입력 지문에 다른 결과는 `non_reproducible`로 거부한다.** 정정으로 입력이 바뀌면 새 스냅샷을 만들고 이전 스냅샷에는 재검토 행이 붙는다. 저장본은 수정하지 않는다.
- **기업분석 보고서는 스냅샷 id만 가리킨다.** 새 보고서의 PER 시나리오·DCF는 스냅샷 한 벌이며 ×0.7/×1.3 표·"현재가 대비" 열·두 번째 DCF는 만들지 않는다. 현재 배수 표는 유지한다. 보고서 열람 응답의 `priceReview`는 응답에만 실리고 저장본을 바꾸지 않는다.
- **표시 문구는 서버 값에서 만든다.** 판정 비교(높음/낮음, 충족/미달)는 부동소수로 다시 계산하지 않고 Decimal 문자열로 한다. 개인 가정 입력은 평문 소수만 받는다(지수 표기 거절).
- **매수·매도·보유, 목표주가, 권장 비중, 확률을 말하지 않는다.** 판정은 "내 기준 대비 충족/미달/알 수 없음"뿐이며 기본 보유 기간의 기본 시나리오로만 한다. 범위 밖(100% 초과·−99% 미만)은 자르지 않고 그대로 표시한다.
- **불가는 이유와 함께 저장한다.** 지원 제한(금융업 등)·주식 수 사건 미확인·이력 부족은 숫자 대신 사유 코드로 저장하고 다른 종목·통화·기준일의 값으로 대신하지 않는다.
- **수집은 사용자가 `계산`을 누르거나 보고서를 생성할 때만 한다.** 읽기 경로는 외부를 부르지 않는다. 계산은 SharedJob 종류 `price_scenario`(종목당 한 번에 하나)이며 저장·링크·재검토 행은 한 트랜잭션이다.
- **검증 증거**(15개 고정 표본의 독립 판독 포함)는 개인 개발용 로컬 계획 폴더(공개 저장소에는 없음)에 있다.

- **새 교차 확인도 층 경계를 지킨다.** A는 현재 PER 유지 IRR을 기준으로 수익률을 성장·배당·PER 변화로 나누고, C는 공시 통화의 원본 합계를 비교한다. 보고서·CLI에는 기본 5·10년 A와 C만 추가한다. B의 정규화 이익에 개인 요구수익률을 적용하는 결과는 가격 탭 투영에서만 읽고 보고서 응답에도 넣지 않는다.
- **이전 기록을 다시 계산하지 않는다.** 방법 1~3의 A·C는 조회 응답에서 `not_applicable(previous_method)` 단일 블록, B는 투영에서 같은 사유다. 현재 method/spec/SHA만 새로 저장한다. 개정 0·SHA 없는 저장본의 참고 숫자는 응답에만 previous_method다. 알 수 없는 SHA의 개인 기준 투영도 previous_method로 제한한다. spec-3 이후 방법 간 공시 정정 표시는 연결하되 SBC 태그 변경은 spec-3↔spec-4에서만 제외한다.
- **주당 계산 제한이 현금 비교를 막지 않는다.** C는 `supported`·`limited`의 공시 원본에서 계산한다. 주가 통화 미상·통화 불일치·주식 수 사건 미확인은 C를 막지 않고, 공시 통화가 없을 때만 `currency_unknown`이다. 오래된 공시는 안내를 붙여 계산한다. 5년 미만·합산 순이익 0 이하에서도 연도별 금액을 보존한다.
