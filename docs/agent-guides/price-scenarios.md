# 가격 시나리오 (가격 탭·투자 기준)

> 이 기능을 변경·검토할 때 [features/price_scenarios/README.md](../../features/price_scenarios/README.md)와 함께 읽는다. 다른 기능의 상세 문서를 일괄 로드하지 않는다.
> 공통 규칙과 § 번호는 [AGENTS.md](../../AGENTS.md)를 참조한다. 코드 경로 표기는 저장소 루트 기준이다.

### 가격 시나리오 (0.9)

- **계산 방식은 동결 명세가 정한다.** `price-scenario-spec-3`(본문 SHA-256 `13e9829d…031b`)과 그 보충 해석이 기준이다. 계산·판정 의미를 바꾸려면 새 명세 버전 → 사용자 승인 → 독립 리뷰를 거친다. 동결 본문은 고치지 않는다. 명세 파일은 로컬 `plan/`에 있어 공개 저장소에는 없다.
- **두 층을 섞지 않는다.** 스냅샷(정본, 입력 지문 고정, `market-memory.sqlite3`의 불변 표)과 개인 층(투자 기준·내 가정, append-only)은 읽을 때 `project()`가 합친다. 개인 층은 스냅샷·보고서·Thesis·포트폴리오를 바꾸지 않는다.
- **같은 입력 지문에 다른 결과는 `non_reproducible`로 거부한다.** 정정으로 입력이 바뀌면 새 스냅샷을 만들고 이전 스냅샷에는 재검토 행이 붙는다. 저장본은 수정하지 않는다.
- **기업분석 보고서는 스냅샷 id만 가리킨다.** 새 보고서의 PER 시나리오·DCF는 스냅샷 한 벌이며 ×0.7/×1.3 표·"현재가 대비" 열·두 번째 DCF는 만들지 않는다. 현재 배수 표는 유지한다. 보고서 열람 응답의 `priceReview`는 응답에만 실리고 저장본을 바꾸지 않는다.
- **표시 문구는 서버 값에서 만든다.** 판정 비교(높음/낮음, 충족/미달)는 부동소수로 다시 계산하지 않고 Decimal 문자열로 한다. 개인 가정 입력은 평문 소수만 받는다(지수 표기 거절).
- **매수·매도·보유, 목표주가, 권장 비중, 확률을 말하지 않는다.** 판정은 "내 기준 대비 충족/미달/알 수 없음"뿐이며 기본 보유 기간의 기본 시나리오로만 한다. 범위 밖(100% 초과·−99% 미만)은 자르지 않고 그대로 표시한다.
- **불가는 이유와 함께 저장한다.** 지원 제한(금융업 등)·주식 수 사건 미확인·이력 부족은 숫자 대신 사유 코드로 저장하고 다른 종목·통화·기준일의 값으로 대신하지 않는다.
- **수집은 사용자가 `계산`을 누르거나 보고서를 생성할 때만 한다.** 읽기 경로는 외부를 부르지 않는다. 계산은 SharedJob 종류 `price_scenario`(종목당 한 번에 하나)이며 저장·링크·재검토 행은 한 트랜잭션이다.
- **검증 증거**(15개 고정 표본의 독립 판독 포함)는 로컬 `plan/audits/valuation-0.9-methodology/`에 있다.
