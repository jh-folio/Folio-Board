# 기업 분석

> 이 기능을 변경·검토할 때 해당 기능 README와 함께 읽는다. 다른 기능의 상세 문서를 일괄 로드하지 않는다.
> 공통 규칙과 § 번호는 [AGENTS.md](../../AGENTS.md)를 참조한다. 코드 경로 표기는 저장소 루트 기준이다.

### 기업 분석

- 시가총액의 모든 `price × shares` 유도 분기는 `marketValueDerivedSafe` 조건을 따른다. 명시 시장가치 통화가 신고 통화와 같아도 주가 통화가 다르면 유도하지 않는다. cap이 없어 계산하지 못한 PSR/FCF Yield와 별도로 검증된 EV/EBITDA를 구분한다.

- 입력은 `build_company_analysis_materials()`에서 구성한다.
- SEC companyfacts, SEC 10-K HTML 상위 문단, 로컬 공식자료 fallback, 점수화된 보조 자료 순서다.
- LLM 버전과 규칙 기반 버전 모두 같은 선별 결과를 사용해야 한다.
- 기업분석은 `analysisStyle=beginner|advanced`를 지원한다. 두 모드는 서로 다른 완전한 prompt 파일을 사용하지만 같은 9개 섹션 골격, 자료 우선순위, no-fabrication, data gap 규칙을 유지해야 한다.
- `service.read_company_analysis_prompt()`는 스타일 prompt에 재무 품질 지침과 `prompts/analysis_focus.md`를 한 번 결합한다. CLI pack과 `request_cli_text` 작성 경계 모두 이 로더를 사용한다. 기업 특성별 질문은 내부 집필 방향으로만 사용하며 목록·문답·중간 계획·신규 필드를 출력하지 않는다. 기존 섹션 전반에서 새 근거·의미·반대 설명을 연결하고 중요한 미확인과 공통 위험 점검을 유지한다. 조건은 출처 있는 수치 또는 확인 가능한 사건으로 쓰며 새 임계치를 만들지 않는다. 조건어 검사는 근거의 타당성을 검증하지 않는다. 추가 호출·계산·자료 수집·규칙 보고서 변경은 없다.
- **beginner 프롬프트는 줄글 안에 스캔 경로를 둘 둔다**(0.6, 실측 A/B 비교 후). 각 문단은 그 문단의 관찰 사실을 담은 강한 첫 문장으로 시작하고(문단 내부 스캔), 0번을 제외한 각 섹션 제목 바로 다음 줄에 blockquote(`> `)로 2~3줄 섹션 요약을 둔다(섹션 간 스캔). 렌더러(`public/app.js`·`MarkdownRenderer.tsx`)가 "헤딩 바로 다음 blockquote"만 `.section-summary`로 스타일한다 — 본문 중간의 일반 인용과 구분하려면 이 순서(제목 → 요약 → 본문)를 반드시 지켜야 한다. §3 밸류에이션 표는 PER·PSR·EV/EBITDA·FCF Yield 같은 배수 뜻을 표 안 열이나 표 아래 한 줄로 밝히도록 명시한다 — 절대 원칙 7의 "처음 나오면 설명"이 실측에서 이 표에만 종종 안 지켜졌다. **볼드는 문단마다가 아니라 섹션당 1~2곳만 쓴다**(0.6 P3, 재수정). 처음에는 이 강한 첫 문장을 매 문단 볼드로도 표시했는데(P1 A/B 비교), 실제 8~9섹션짜리 전체 보고서로 보니 모든 문단이 볼드라 오히려 강조가 사라졌다(사용자 실측 지적: "너무 일관적으로 볼드만 넣어서 강조되는 느낌이 안 나네") — P1의 짧은 스니펫 비교로는 안 보이던 문제였다. 문장 자체는 계속 강하게 쓰되, 마크다운 볼드는 그 섹션에서 판단을 좌우하거나 가장 의외인 사실 1~2곳에만 남긴다.
- **섹션 요약 blockquote와 소제목 사이 간격이 0이었다**(`public/styles.css`, 0.6 P3). `.markdown-brief h3 + p`·`h3 + ul`에는 0.58em 간격 규칙이 있었지만 blockquote는 그 목록에서 빠져 있었다 — `h3`가 `margin-bottom: 0`, `blockquote`가 `margin: 0 0 1em`(top 0)이라 섹션 요약이 추가된 이후로 소제목 바로 아래 blockquote는 계속 간격 없이 붙어 있었다. `h3 + blockquote`를 같은 규칙에 추가해 다른 헤딩-다음-요소 간격과 통일했다(0px → 약 10px, `getComputedStyle`로 확인).
- 제공 자료가 부족하면 먼저 `features/company_analysis/data_gap_resolver.py`로 확인 경로와 미해결 항목을 구조화하고, 보고서 JSON에는 `dataGaps`와 `resolutionAttempts`를 보존한다.
- 보고서는 생성 시 `data/company-analysis/`에 **자동 저장**된다(`api_analyze`가 `save_analysis_report` 호출). 보고서 id는 `ticker:날짜` 기준이라 같은 기업을 같은 날 재분석하면 최신본으로 덮어쓴다(파일 무한 누적 방지). 덮어쓸 때 기존 `personalOverlay`는 보존한다.
- 영어 10-K 원문은 규칙 기반 보고서에서 그대로 나올 수 있다. 번역은 브라우저 번역이나 LLM 버전에 맡긴다.

- **분기 자료**: companyfacts 분기 행은 이미 컨텍스트 표(`Recent Quarter`)에 들어간다. 차트는 연간만 읽고 있어서 `분기 흐름` 차트를 따로 만든다(최근 8개 기간, **전년 동기 대비** — 분기는 계절성이 있어 직전 분기와 비교하면 오해한다). 10-Q 서술은 `rankedQuarterlyFiling`으로 붙는다. 10-Q는 Item 번호 체계가 10-K와 달라(`Item 2` = MD&A) `_ITEM_PATTERNS`·`_ITEM_EQUIVALENTS`에 따로 등재돼 있다.
- **출처 목록**: reader가 표시하는 `sources`는 `company_analysis_sources()`가 만든다. 컨텍스트가 근거로 읽는 것은 전부 여기에 있어야 한다(P0) — 연차보고서(`rankedFiling`)와 **최근 10-Q(`rankedQuarterlyFiling`)를 각자 form 라벨과 함께** 싣고, `secFacts`의 companyfacts 링크는 submissions가 아니라 **실제 companyfacts API URL**(`SEC_FACTS_URL`)을 가리키며, 웹 조회로 인용한 자료(`webSourceItems`)도 `sourceLedger`뿐 아니라 `sources`에 들어간다. `sources`·`sourceLedger`·본문 인용·내보내기는 같은 자료의 호환 표현이다.
- **차트 계약**: 값이 하나도 없는 계열은 그리지도 **부제에서 약속하지도** 않는다(`_present_subtitle`). 마진처럼 단위가 다른 계열은 오른쪽 축으로 분리한다 — 금액 축에 얹으면 0에 붙어 사라진다. 기간 구간이 hover 대상이고 그 기간의 모든 계열과 증감을 그림 밖 고정 상자에 보여준다.
- **차트 배치**: reader(`CompanyAnalysisBody`)는 차트를 섹션에 **2-pass**로 배정한다(P0) — 전체 섹션의 의미 매칭(제목 키워드)을 먼저 끝내고, 남은 차트만 고정 위치(`fallbackIndex`)로 떨어뜨린다. 인덱스 fallback을 먼저 소비하면 "기업 개요"가 뒤 "실적과 재무 품질"의 실적·마진 차트를 가져간다. 서론(intro) 문단이 붙어도 `fallbackIndex`는 배열 위치가 아니라 헤딩 순번(`headingOrdinals`) 기준이라 밀리지 않는다.
- **참고자료 이후 본문**: 공통 `ReportBody::stripInlineReferenceSections`와 `public/app.js::markdownSourceSection`은 참고자료 헤딩부터 **다음 동급·상위 헤딩까지만** 걷어낸다(P0). 문서 끝까지 자르면 그 아래에 온 정상 섹션("밸류에이션과 DCF 관련 주의" 등)이 사라진다. 브리핑처럼 참고자료가 문서 맨 끝이면 헤딩부터 끝까지 제거되어 기존 동작과 같다.

- **기업분석도 산출물 계약을 갖는다**(0.5.4). 계약을 프롬프트에만 두고 결과를 확인하지 않으면 지켜지지 않는다 — `REQUIRED_SECTION_HEADINGS` 9개가 정의돼 있었지만 그것을 쓰는 함수는 프롬프트 파일 검사 하나뿐이었고, 실측 4건 중 3건이 계약과 다른 제목을 쓰며 두 섹션을 통째로 빠뜨렸다. `company_analysis/report_contract.py`가 섹션 누락·분량·근거 연결·문체를 결함으로 잡고 `depth_policy.py`가 섹션 예산을 정한다. **목표 분량은 확보한 자료를 따라간다** — 고정 하한을 두면 자료가 0건인 회사에서 없는 이야기로 칸을 채운다. **어느 결함도 산출물을 되돌리지 않는다**(후보·재시도 구조가 없어 차단하면 사용자가 아무것도 받지 못한다). 숨김 근거 태그가 0개여서 `source_grounding`이 0.08~0.42였으므로, 인용 가능한 ID 목록과 태그 형식을 생성 컨텍스트에 함께 싣는다. 계약 결함 상한은 딥 리서치와 같은 눈금(`common/research_quality/contract_ceiling.py`)을 쓴다.

- **기업분석의 자료 조립과 검증은 공통이다.** CLI와 규칙 생성은 `generation_context.py::build_generation_inputs()`로 자료·컨텍스트를 모으고 `finalize.py::finalize_report()`로 검증·상한을 적용한다. 기업 식별·검색어·requiredSections·웹 검색 값이 실제 호출부에서 같게 전달되어야 한다. CLI 구조 보완 실패 시 초안을 보존하고 검증 미완료를 표시한다. `engine_calls`는 순환 import를 피하도록 브리지를 호출 시점에 import한다.
- **밸류에이션은 한 곳에서 계산한다**(`company_analysis/valuation.py`, 0.5.4). 본문과 차트가 각자 계산하던 시절 한 보고서에 시나리오가 두 벌 있었다 — 실측 HWM 심화가 본문 `EPS 5.54 × 30/45/60배 → $166/$249/$332`, 차트 `EPS 4.081 × 54/73/94배 → $222/$296/$385`를 나란히 실었고 본문 안에서도 45x와 35x가 충돌했다. 게다가 차트 계산은 **항등식**이었다 — forward EPS(`trailing×(1+성장률)`)에 **trailing PER**을 곱하니 기본 시나리오가 정의상 `현재가×(1+성장률)`이라 어떤 회사든 상승으로 나왔다. 지금은 EPS와 PER의 기준을 맞춰(forward EPS ↔ forward PER) 기본 시나리오가 정확히 현재가가 되고("지금 배수가 유지되면 지금 가격"), 차트와 생성 컨텍스트가 같은 객체를 읽으며 컨텍스트가 "이 표를 다시 계산하지 마세요"로 못박는다. **배수는 여전히 가정이다** — 비교 기업·과거 밴드 자료가 없으므로 현재 배수 대비 비율(×0.7/×1.0/×1.3)로만 두고 객체가 그 사실을 스스로 밝힌다(`multipleBasis`). 근거를 만들 수 없으면 있는 척하지 않는다.
- **통화·단위가 다른 계산만 제외하고 보고서는 유지한다.** `valuation_basis.py`를 규칙/차트와 CLI 공통 조립기가 사용한다. 신고/주가/시장가치/공급자 재무 통화를 구별하며, 미확인 통화를 USD로 채워 계산하거나 GBp를 GBP로 값 변환 없이 합치지 않는다. 명시 ADR 비율·주식종류 불일치는 영향 주당 계산을 제외한다. 메타데이터가 없다는 사실을 비율 검증 완료로 올리지 않는다. 공급자 현금흐름은 자체 통화가 신고 통화와 일치할 때만 결합한다. `analysisCharts.valuationBasis`와 unavailable 사유를 저장하고 사업/재무/본문을 보존한다. 새 FX·ADR 환산, 기존 저장본 재작성, 임의 LLM 산문의 정확성 보증은 이 최소 정책에 포함하지 않는다.
- **통화 라벨이 같아도 크기가 틀릴 수 있다**(`report_rules.py::build_valuation_metrics`, 0.6 P3). `financialCurrency` 재확인은 통화 *라벨*이 다를 때만 제공자(yfinance) EBITDA를 SEC/DART 값으로 되돌린다 — 라벨이 같은데 크기 자체가 틀린 경우(실측 000660.KS: yfinance EBITDA가 매출의 약 11배로 나와 EV/EBITDA 1.2배라는 결과를 냈다)는 못 잡는다. 그래서 EBITDA가 매출을 넘으면(정상 영업기업의 EBITDA 마진은 100%를 넘지 않는다) 통화 문제가 아니라 원본 데이터 오류로 보고 계산에 안 쓴다 — SEC/DART 값이나 "확인 필요"로 내려간다.
- **지표군마다 자료가 있는 해의 폭이 다르면, 차트마다 자신의 폭만 쓴다**(`service.py::build_company_analysis_charts`, 0.6 P3). 예전에는 `years` 하나를 손익 4종(매출·매출총이익·영업이익·순이익)과 현금흐름 2종(영업활동현금흐름·설비투자) 전체의 union으로 잡았다. 현금흐름 2종은 yfinance `cashflowRows`로 보강되어 손익 4종보다 한 해 더 먼 과거를 갖는 경우가 실측됐다(000660 SK하이닉스: DART 손익은 2023년부터, 보강된 현금흐름은 2022년부터). 공유된 `years`에 그 2022년이 섞여 들어가면서 "실적 추이"·"마진 추이" 차트가 2022년을 라벨로 그리고 값은 전부 null인 빈 점을 냈다 — 실제로는 자료가 없는 게 아니라 다른 지표군의 폭을 빌려온 것이었다. 지금은 `performance_years`(손익 4종 union)와 `cashflow_years`(현금흐름 2종 union)를 따로 잡아 각 차트가 자기 폭만 쓴다. `fcfMargin`의 분모(매출)는 `cashflow_years` 폭으로 다시 읽는다 — `performance_years` 폭의 매출을 그대로 zip하면 두 폭이 달라질 때 해가 한 칸씩 밀려 어긋난다.
- **본문 제목 줄의 `#`는 프롬프트가 아니라 `finalize_report`가 보장한다**(`finalize.py::_ensure_markdown_title`, 0.6 P3). 프런트엔드(`CompanyAnalysisRoute.tsx`·`app.js`의 `splitReportTitle`)는 markdown 첫 내용 줄이 `# `로 시작해야 그 줄을 카드 제목으로 뽑아 본문에서 지운다. 규칙 기반 경로(`render_report`)는 `# ✅ 이름 (티커)`를 항상 써서 문제가 없었지만, CLI/LLM 경로는 모델 출력에 그대로 의존해 형식이 흔들렸다 — 같은 세션 실측으로 RIVN은 `# Rivian ...`으로 맞았지만 SK하이닉스는 `#` 없이 "SK하이닉스(000660) 기업 분석"으로 시작해, splitReportTitle이 못 찾고 그 줄이 카드 제목 바로 아래 스타일 없는 문단으로 남아 제목이 두 번 보이는 것처럼 렌더링됐다. **프롬프트에 형식 지시를 추가하는 대신**(RIVN도 지시 없이 우연히 맞았을 뿐이라 신뢰할 수 없다) CLI 공통 마감 지점(`finalize_report`)에서 첫 heading(`#`/`##`) 앞의 내용을 전부 headline으로 통일한다. 첫 줄이 이미 `# `면 손대지 않고, 헤딩이 전혀 없는 문서(구조 자체가 깨진 경우)도 손대지 않는다 — 그런 문서는 계약 검증이 따로 잡아야 할 더 큰 결함이라 여기서 원문을 지우면 결함을 숨기게 된다. **이미 저장된 보고서에는 소급 적용되지 않는다.**
- **자사주 매입은 금액만으로 평가하지 않는다**(`buyback.py`, 0.5.4). 금액만 주면 본문도 금액만 쓰고, 그러면 매입은 언제나 주주환원으로 읽힌다(실측 HWM 보고서가 `$700M/$500M/$250M`을 나열하고 "적극적 주주환원"이라 적었다). **주식 수가 줄지 않는 매입은 환원이 아니라 희석 상쇄다.** 주식보상 상쇄 비율·희석주식수 전년 대비·매입 수익률을 함께 싣고, 평균 매입가는 회사가 매입 주식 수를 공시했을 때만 낸다(`TreasuryStockSharesAcquired`를 등재하지 않는 회사가 많다 — 실측 HWM 없음). **판정은 하지 않는다** — 비율을 계산해 보여줄 뿐 좋다·나쁘다는 근거를 본 본문이 쓴다(§5 원칙 4).
- **섹터와 산업은 같은 분류 체계에서 나온다.** SEC의 SIC 서술을 섹터에 먼저 넣던 시절 한 보고서가 `sector: Rolling Drawing & Extruding of  Nonferrous Metals`(SIC 원문, 공백 둘)와 `industry: Aerospace & Defense`(yfinance GICS)를 나란히 실어, 독자에게는 두 분류가 서로를 부정하는 것처럼 보였다. SIC는 둘 다 없을 때의 마지막 보루이며 연속 공백과 `Unclassified` 같은 자리표는 정규화한다.
- **내부 용어는 본문에 나가지 않는다.** `partial`·`data gap`·`Thesis가 바뀌는 trigger` 같은 말은 상태 관리용이지 독자의 말이 아니다. 계약이 `INTERNAL_TERMS`로 잡고(`internal_term_leak`), 컨텍스트가 대체 표현("자료 한계"·"판단이 바뀌는 조건"·"일부 확인")을 함께 가르친다 — 검사만 하고 알려주지 않으면 모델은 계속 같은 말을 쓴다.
- **DCF는 `dcf.py` 하나가 소유한다**(0.5.4). 예전 모델의 문제는 정교함이 아니라 **모든 회사에 같은 답을 준다**는 것이었다 — 실측 5개사가 전부 "현재가의 37~62%"였고(HWM $71/$188, NVDA $85/$180, AAPL $88/$230, MSFT $109/$430, LRCX $76/$95) 매번 심한 고평가를 말하는 모델은 판단의 재료가 아니라 상수다. 원인이 넷이었다. (1) 성장률 클램프 `[-3%, +10%]`에 6개사 중 5개가 물려 성장률이 사실상 상수였다. (2) 성장이 5년 평탄 후 터미널로 급락했다. (3) 할인율이 9% 고정이라 부채비용 3.03%(NVDA)~7.28%(MSFT), 세율 12.1%~19.4%의 차이가 전부 무시됐다. (4) 기준 FCF가 최근 1년이라 NVDA 96.7B(3년 중앙값의 1.6배)·HWM 1.43B(1.5배)처럼 한 해가 회사 전체의 가치를 정했다.
- **기준 FCF는 마진으로 정상화한다.** FCF 마진은 안정적인데(실측 3년 변동 NVDA 2.3%p·TSLA 2.9%p·AAPL 4.1%p) 금액은 아니다. 마진을 고정 중앙값으로만 쓰면 **다년간 완만하게 개선(또는 악화)되는 회사에서 정상화가 항상 한두 해 뒤처진다** — 실측 HWM(마진 10.3%→13.2%→17.3%, 우량성장주형)이 중앙값(13.2%)을 쓰면 2025년 실제 FCF보다 24.2% 낮은 기준값이 나와, 이후 역산 성장률(§역산 성장률)이 실제보다 더 공격적으로 보인다. 그래서 `_margin_trend()`가 먼저 완만한 다년 추세인지(한 구간이 마진 폭의 70%를 넘지 않는지) 본다 — 넘으면 스파이크(예: CapEx 급증 한 해)이지 추세가 아니므로 기존 중앙값으로 내려간다. 추세로 판정되면 최근 연도에 선형 가중한 평균(`method: trend_weighted_margin`)을 쓰고, 아니면 기존 중앙값(`median_margin`)을 쓴다 — 안정적 캐시카우형은 원래 방식 그대로다. 어느 쪽이든 최근값과의 차이(`deviationFromRecent`)와 추세 방향(`marginTrend`)을 함께 낸다. **성장은 매출에서 온다** — FCF 성장률은 매출과 부호까지 어긋난다(실측 MSFT 매출 +10% vs FCF −3.0%, TSLA −1.0% vs +10%). 정상화 FCF가 `마진 × 매출`이므로 마진을 고정하면 성장의 출처도 매출이어야 모델이 스스로와 일관된다.
- **명시적 예측 기간은 10년이고 성장은 감쇠한다.** 5년이면 터미널 비중이 65~75%라 DCF가 현금흐름 모델이 아니라 터미널 베팅이고, 고성장 기업 둘은 역산 성장률이 탐색 범위 밖으로 나가 답 자체가 없었다. 10년에서는 47~60%로 내려가고 다섯 곳 모두 풀린다. **터미널 비중을 반드시 공시한다** — 숨기면 독자는 정밀한 현금흐름 모델을 봤다고 생각한다. **문구의 연차 숫자는 `fadePath` 길이를 따라간다**(P0) — "6년차 이후"로 박아 두면 10년 모델에서 터미널이 11년차부터라는 사실과 어긋나고, 본문이 그 오류를 그대로 옮긴다. `render_dcf_context`(LLM 컨텍스트)와 `report_rules` 셀이 같은 "명시 예측 기간 N년 이후" 표현을 쓴다.
- **할인율은 회사별 WACC다.** 무위험수익률 + 조정베타×위험프리미엄, 세후 부채비용, 시가 기준 가중. **베타는 블룸 조정한다**(`2/3×원시 + 1/3×1`) — 원시 베타 2.12를 CAPM에 그대로 넣으면 할인율 14.8%를 받아 어떤 성장률로도 현재가가 설명되지 않는다. 모델이 답을 못 내는 것이지 그 회사가 그만큼 위험한 것이 아니다. 입력이 없으면 예전 고정값(9%)으로 내려가되 **그 사실을 보고서가 밝힌다**. 무위험수익률과 위험프리미엄은 가정이다 — USD 무위험은 `risk_free.py::current_risk_free()`가 살아 있는 값(FRED `DGS10` → `^TNX`, 1일 TTL 캐시)을 두 생성 경로에 주입하고 출처를 `riskFreeMeta`에 남기며, 조회 실패·비USD는 통화별 상수로 내려간다(`dcf.py`는 계속 스스로 조회하지 않는다). **두 입력이 답을 얼마나 지배하는지는 가정 감도표가 공시한다**(`assumptionSensitivity` — 무위험 ±0.5%p·ERP 4/5/6% 축의 내재가치·역산 성장률 밴드. 실측 ERP 4~6%가 MSFT 내재가치를 37% 흔든다). 내재가치는 하나의 값이 아니라 이 범위로 읽는다.
- **역산 성장률이 이 층의 핵심 숫자다.** "현재가가 정당화되려면 초기 성장률이 몇 %여야 하는가"를 이분법으로 푼다. 모델이 "62% 고평가"라고 판정하는 것보다 "시장은 연 45% 성장을 가격에 넣고 있다"가 정보이고, 그 숫자가 그 사업으로 가능한지는 사람이 판단한다(§5 원칙 4). 본문 컨텍스트·규칙 보고서·차트 카드가 모두 이 값을 싣고 **고평가·저평가로 단정하지 말라**고 함께 적는다. **이 값은 1년차 FCF 성장률이며 이후 N년에 걸쳐 영구성장률까지 감쇠한다**(P0) — 여러 해 유지되는 성장률이 아니고, 정상화 FCF·할인율·영구성장률·감쇠 경로를 고정하고 초기 성장률 한 변수만 역산한 결과다. 매출·EBITDA 성장률 한 숫자와 그대로 비교하지 않도록 컨텍스트가 그 조건을 함께 싣는다.
- **순부채에 단기차입을 넣는다.** 장기부채만 보면 유동성 차입이 많은 회사의 부채가 통째로 사라진다(`Short-Term Debt`를 0.5.4에 등재). **시나리오는 사업 가정만 흔든다** — 성장·할인율·영구성장을 한꺼번에 움직이면 세 가정이 겹쳐 범위가 인위적으로 넓어지고 무엇 때문에 차이가 났는지 알 수 없다. 평가 가정(할인율·영구성장)은 민감도 표가 맡으며, **그 표도 시나리오와 같은 모델을 쓴다**(예전에는 민감도만 5년 평탄이라 같은 할인율에서 두 표가 다른 값을 말했다). 추정 상한과 시나리오 상한은 다르다 — 같이 쓰면 추정이 상한에 물린 회사에서 낙관이 기준과 똑같아진다(실측 NVDA 둘 다 30.0%).
- **차트·본문 컨텍스트·규칙 보고서가 같은 DCF 객체를 읽는다**(`analysisCharts.dcf`). `financial_engine`의 옛 5년 평탄 모델은 제거했다 — 두 벌이 있으면 어느 표가 어느 모델에서 왔는지 알 수 없게 된다. 시장 데이터 캐시에 `beta`를 추가하며 `MARKET_CACHE_SHAPE`를 올렸다(안 올리면 beta 없는 옛 캐시가 TTL까지 내려와 할인율이 조용히 고정값으로 떨어진다).
- **웹 검색 설정은 공통 resolver로 해석한다.** 요청의 `webSearch`가 생략되어 `None`이면 저장된 설정을 따르며, `bool_override(...) is True`로 축약해 검색을 끄지 않는다. 실제 전달값과 `webLookup`·`sourceLedger` 결과를 검증한다.
- **기업분석도 웹으로 자료 공백을 메운다**(0.5.4). 로컬 색인은 보관 기간상 약 3개월이라 뉴스가 거의 없는 종목은 구조적으로 못 채운다(실측 로컬 문서 11/5/2/0건). 딥 리서치와 같은 **찾기 전용** 패스이며 최근 실적·가이던스·**경영진 실제 발언**을 찾는다. 발동 조건은 보조 자료 6건 미만이거나 실적·IR 갭이 있을 때라 대부분의 실행에서 호출이 늘지 않는다. **화자 귀속은 이름으로 본다** — `CFO`는 직함 목록에 넣지 않는다(기업분석 본문에서 그 세 글자는 대부분 영업현금흐름이라 재무표만 있어도 귀속이 통과한다). 초안이 고정 9섹션을 어기면 쓰기만 한 번 더 시키며(`draftGuard`) 실패한 초안은 되돌려 주지 않는다. 서술 요구(분석 범위 선언·조건형 시나리오)의 조건 낱말은 **품질 평가기가 세는 목록 그대로** 쓴다 — 넓히면 계약은 통과시키고 점수는 안 오르는 표현을 가르치게 된다.


### 부분 완료와 복구 후보 (2026-09-21)

- CLI 원문 이벤트는 저장하지 않고 공통 `cli_completion.py`가 관측한 종료 사실만 전달한다. Codex turn 완료/실패, Claude result/출력 한도/도구 대기를 구분하고 미관측은 unknown으로 둔다. native citation·provider continuation 전체(E0)는 이 최소 종료 관측과 별도다.
- `finalize_report`는 provider 종료와 구조 누락을 `completion`에 구분한다. 본문 작성과 기업분석 quality repair에 적용한다. 불완전/실패 후보는 `canonical_reports.prepare`의 기업분석 전용 guard가 차단해 sync/job/quality 저장에서 정본을 덮어쓰지 못한다. 기존 CAS·revision·Overlay 계약은 유지한다.
- 받은 CLI 본문 및 최종 저장 후보는 `company-analysis/recovery/`에 atomic write로 보관한다. 후보는 기존 목록/상세/삭제 API로 접근하며 saved=false와 고정 안내를 표시한다. 정본·Change Intelligence·Overlay 입력으로 자동 승격하지 않는다. 정상 커밋 증명 뒤 같은 본문의 복구 사본만 정리한다. 중단/실패 후보는 자동 삭제·자동 재실행하지 않는다.
- 복구 보장은 후보의 원자적 쓰기 완료 이후부터다. provider 내부의 미반환 토큰이나 저장 장치 자체 실패까지 보장하지 않는다. 실제 CLI 생성/사용자 독해는 별도 선택이며 완료 조건이 아니다.
